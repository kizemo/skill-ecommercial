# ch03 · 动态调级与监控

> 用途：定"多久看一次、看什么数、什么数触发升级/降级"，以及怎么把监控做成能落地的表。

---

## 一、复盘频率

| 级别 | 频率 | 理由 |
|---|---|---|
| **S 级** | **每月** | S 级体量大、影响全店权重，但指标变化以月为单位 |
| **A 级** | **每半月** | 利润主战场，变化比 S 快 |
| **B 级** | **每周** | 量小变化快，需及时升/降 |
| **C 级** | **每日** | 止损要快，连续 30 天无销量要能提前识别 |

**另一套口径**：三阶引擎工具表明确「**SAB 分级每 30 天重新评估一次**」，与"S 级/月"一致；A 级的"每半月"（15 天）在 SAB 体系里没有对应，是 SABC 体系独有的加严节奏。**口径冲突，需复核**——如果店里用的是三阶引擎工具表，就按 30 天全量重评，不要一半链接 15 天一半 30 天。

**红绿灯监控法的监控周期规则**（同一逻辑的通用表述）：业务变化快的指标（如素材爆款率）→ 按周监控；业务变化慢的（如新品上市数量）→ 按月监控。

---

## 二、定期评估的五个指标

**每次评估五项都过一遍**，不要只看销量：

| 指标 | 看什么 | 判据来源 |
|---|---|---|
| **销量** | 绝对值与环比 | S/A/B/C 的数量阈值 |
| **销售额** | 占比（决定是否够格做 S） | 销售额占比 > 40% → S 候选 |
| **投产** | 推广投产 vs 总投产 | 推广投产 < 店铺均值 → 禁止盲目加预算 |
| **利润率** | 毛利率与净利率 | 毛利率 > 30% → A 候选；< 20% → C |
| **增长率** | 30 天趋势 | 潜力爆款：30 天增长 30%+ |

**看数顺序**：先用"销量 + 增长率"判断势能（是不是该升），再用"销售额占比 + 关联销售率"判断能不能升到 S，再用"投产 + 利润率"判断升上去之后会不会亏钱。

## 三、调级规则表

| 调整方向 | 条件 | 配套动作 |
|---|---|---|
| **A→S** | 表现好的 A 级产品升级 | 加预算至 S 档；提前安排供应链；开始按 S 级定价（80-90% 均价）做测试 |
| **B→A** | 表现好的 B 级产品升级 | 加预算至 A 档；配"控投产计划 + 好货快投" |
| **S→A** | 表现差的 S 级产品降级 | 收回大部分预算；改 A 级定价（100-120% 均价） |
| **A→B** | 表现差的 A 级产品降级 | 转低预算养人群；长尾关键词为主 |
| **清仓处理** | **连续 3 个月表现差的 B 级产品** | 进 C 级处理流程：降价清仓 / 捆绑 / 直播 / 报废 |
| **C 级复活** | 素材、价格、供应链变更后重新起量 | 重新按 C 级候选测款流程走（新品运营中心 + 低预算测试） |

**升级优先于降级的观察顺序**：先看有没有该升的，再看有没有该降的。全程只看降级，分级体系会单调收缩，最后只剩一堆 C 级。

## 四、调级前的两个财务闸门

**看板数据会骗人，调级前必须过算账。** 公式全文在 [[profit-model]]。

### 闸门 1：真实投产是否高于盈亏平衡 ROI

```
真实投产 = 投产 × (1 − 退款率) × (1 − 间接成交占比) × 拉新成交
盈亏平衡 ROI = 1 ÷ 毛利率
```

- 真实投产 **<** 盈亏平衡 ROI → **不升**。看板上的高投产可能是收割老客凑出来的。
- 看板投产漂亮但真实投产不达标 → 典型动作是**先停投再重测**，不是加预算。

### 闸门 2：顺逆差方向

```
顺逆差 = 单品成交金额占比 − 单品推广花费占比
```

| 顺逆差 | 含义 | 动作 |
|---|---|---|
| **正向顺差** | 花小钱办大事 | **预算倾斜**（这是加预算的核心依据） |
| **负向顺差** | 花钱多产出少 | 优化或淘汰 |
| **零顺差** | 收支平衡 | 维持观察 |

**组合判断表**：

| | 顺逆差正向 | 顺逆差负向 |
|---|---|---|
| **真实投产达标** | 升级候选，加预算 | 先优化投放结构，再看 |
| **真实投产不达标** | 可能是免费流量在扛，检查品类竞争力 | 降级或止损 |

## 五、监控工具：红绿灯监控法

灵感来自丹纳赫公司的 DBS 业务系统。用三色让任何人都能一眼看懂指标状态。

| 颜色 | 含义 | 行动 |
|---|---|---|
| 🟢 **绿色** | 指标达成目标 | 总结经验，继续保持 |
| 🟡 **黄色** | 接近目标，还需努力 | 分析原因，及时调整 |
| 🔴 **红色** | 未达成目标 | 重点关注，制定改进计划 |

### 实施四步

1. **确定监控指标**（来自战略指标拆解）。电商公司的候选：测款数量、新品转化率、库存周转率、ROI。**每部门不超过 3 个关键指标**。
2. **设定目标值**。参考公司历史数据、行业平均水平、战略目标。目标应该是"跳一跳，够得着"的。
3. **制作红绿灯表**。格式固定为：
   `指标名称 | 目标值 | 实际值 | 完成率 | 颜色 | 改进措施`
4. **定期更新与复盘**。快指标按周、慢指标按月；每月开战略复盘会。

### 红绿灯用在分级上的映射

| 监控对象 | 绿灯 | 黄灯 | 红灯 |
|---|---|---|---|
| 链接等级 | 稳定在当前级别且指标达标 | 接近边界，观察 | 掉出本级标准，准备降级 |
| 预算分配 | 花在该级的钱产出占比达标 | 产出低于占比 | 产出远低于占比 |
| 库存周转 | ≥ 本级要求 | 接近下限 | 低于下限（C 级预警） |

### 红绿灯的四个误区

| 误区 | 正确做法 |
|---|---|
| 与绩效考核直接挂钩 | 目的是找到问题持续改进，不是奖惩 |
| 指标太多太杂 | 每部门 ≤ 3 个关键指标，抓住主要矛盾 |
| 只看数据不看过程 | 分析指标为什么是绿/黄/红色，找出真正原因 |
| 一成不变不做调整 | 动态调整，当某指标已成常态时换新的重点 |

**这一条对分级尤其重要**：把红绿灯直接挂到奖金上，S 级会立刻变成"不赚钱不许做"，S 级使命（击穿类目、获取人群资产）当场失效。

## 六、三阶引擎的 8 维度准入（调级的第二道关）

除了看 SABC 的五个指标，三阶引擎在"品为店贡献"层用 **8 维度考核**筛出值得推广的产品：

| 维度 | 说明 |
|---|---|
| 搜索展现价值 | 搜索点击率 × 转化率 × 客单价 |
| 搜索支付转化率 | 搜索成交访客 / 搜索总访客 |
| 平均停留时长 | 详情页承接能力 |
| 跳失率 | 页面跳出比例 |
| 退款率 | 货品质量与描述一致性 |
| 连带购买率 | 多品类协同能力 |
| 连带购买叶子类目宽度 | 跨类目覆盖度 |
| 复购率 | 用户粘性 |

**准入标准：6 分以上才值得推广，6 分以下必须先优化。**

**用法**：一个链接 8 维度不到 6 分，**先修产品再谈分级**。把它升成 B 级或 C 级都没用——它的问题不在资源分配层，在产品层。修完再重新参与分级。

**调级后还有第三层**：人群计划分层（拉新/追投/收割），见下节。

---

## 七、人群计划三层与调级的衔接

| 计划类型 | 人群 | 出价策略（盈亏比 + 成交新客比） |
|---|---|---|
| **拉新** | 智能推荐人群等 | 盈亏比 **> 0.8** + 新客比 **> 80%** |
| **追投** | 流失摇摆 / 频繁搜索 / 喜欢本店 | 盈亏比 **< 0.5** + 新客比 **> 50%** |
| **收割** | 历史购买 / 会员 / 复购人群 | 盈亏比 **< 0.4** + 新客比 **< 40%** |

**借壳复制法**：复制历史拉新/追投/收割各 3-5 个计划换品，保持场景/出价/人群/创意不变，启动观察 3-7 天，确定性提升 80%+。

**调级衔接**：链接级别决定它配什么计划（S 级配全站+直通车+引力魔方，C 级只配好货快投/新品运营中心）；计划类型决定链接在"拉新/收割"里的角色。**同一条链接被反复升不是因为数据变好，而是因为人群池被切换了**——所以调级记录里要写清楚换的是人群还是链接本身。

## 八、调级会议模板

```
【本期待调级清单】
链接ID | 上期等级 | 本期等级 | 触发指标（销量/销售额/投产/利润率/增长率）
      | 真实投产 | 顺逆差 | 8维度得分 | 依据 | 动作 | 责任人 | 完成日期

【无变化但要说明的】
链接ID | 处于边界 | 差多少 | 下期观察点

【本期待止损清单】
链接ID | 等级 | 连续无销量天数 | 处理方式（清仓/捆绑/直播/报废）| 库存金额
```
