# 诊断节奏与问题对照表

**来源笔记**：《店铺诊断四层分析法》《红绿灯监控法》《淘系运营核心公式》

---

## 一、日常节奏

```
每天：
1. 看营销产品报表 → 整体费率是否异常
2. 看商品报表 → 花销前 5 品是否间接成交比过高
3. 看单品领先率 → 是否 < 80%

每周：
1. 做定向分析 → 清理跑收割的定向
2. 监控竞品 → 调整出价策略
```

**每天的顺序不能换**：先看店铺层（有没有异常品），再看花销 Top 品（钱花在哪），最后看领先率（拉新还是收割）。倒过来做会变成"先挑指标再找解释"。

**为什么"花销前 5 品"是固定范围**：诊断要的是可执行清单，不是全店普查。前 5 品通常覆盖绝大部分推广花费，砍掉这 5 个还剩下的问题优先级必然更低。

## 二、常见诊断问题与解决方案

| 问题现象 | 根本原因 | 解决方案 |
|---|---|---|
| 投产高但销售下滑 | 间接成交占比过高，只在收割老客 | 优化定向，加强拉新 |
| 某品领先率 < 50% | 主要在收割，不在拉新 | 暂停该品或重新测试 |
| 去掉某定向后省了钱销售没变 | 本来就在收割 | 继续清理无效定向 |
| 投产数据"假好" | 归因计算方式问题 | 切换到第一次 / 最后一次访问来源验证 |

**四条现象的共同点**：钱没有花错地方，是**花在了收割上**。所以四条的对策都指向同一件事——把流量重新指向拉新。

## 三、接上红绿灯监控法

诊断结论要能落到日常执行，否则下次还会犯同样的错。用红绿灯监控法把关键指标固定下来：

| 颜色 | 含义 | 行动 |
|---|---|---|
| 🟢 绿色 | 指标达成目标 | 总结经验，继续保持 |
| 🟡 黄色 | 接近目标，还需努力 | 分析原因，及时调整 |
| 🔴 红色 | 未达成目标 | 重点关注，制定改进计划 |

**实施要点**：

- 每部门**不超过 3 个关键指标**（诊断类建议：店铺领先率、花销 Top5 品间接/直接比、月度费比）
- 目的是找到问题持续改进，**不直接与绩效考核挂钩**
- 业务变化快的指标按周监控，变化慢的按月监控
- 指标太多太杂是头号误区

**红绿灯表格式**：指标名称 | 目标值 | 实际值 | 完成率 | 颜色 | 改进措施

## 四、诊断记录模板

每次诊断产出一张表，下一次照着这张表复盘：

| 字段 | 填写内容 |
|---|---|
| 诊断日期 / 时间窗 | 与上次是否可比 |
| 店铺领先率 | 档位判定 |
| 异常品清单 | 第 1 层产出 |
| 命中品（间接 ≈ 2× 直接） | 第 2 层产出 |
| 命中品领先率 | 第 3 层产出 |
| 收割定向清单 | 第 4 层产出 |
| 预计月省广告费 | 停定向收益公式 |
| 转交动作 | 调级 / 调计划 / 修人群 / 算账 |

## 五、诊断结论落点（不要在诊断里越权）

| 诊断结果 | 归属 skill | 不要做什么 |
|---|---|---|
| 某品该降级、该停 | [[sabc-product-tiering]] | 不要自己改分级 |
| 计划组合、预算重排 | [[wanxiangtai-wujie]] | 不要自己调出价 |
| 人群不准、拉新链路断 | [[customer-asset-ops]] | 不要直接加预算硬拉 |
| 投产去伪、算账、斩杀线 | [[profit-model]] | 不要用投产当利润 |
| 全局定位、核心公式 | [[taobao-ops-playbook]] | — |

**一条硬规则**：诊断阶段**不调出价、不加预算、不改分级**。诊断只产出结论和清单，变更动作由对应 skill 执行，否则同一份数据会被反复动，看不清哪个动作有效。

## 六、诊断没跑出结论时的兜底顺序

| 顺序 | 检查 | 说明 |
|---|---|---|
| 1 | 归因方式是否切换 | 默认归因会让所有数据失真，先切 |
| 2 | 时间窗是否对齐 | 报表与推广数据不同窗，比出来的比值无意义 |
| 3 | 是否只看店铺层 | 必须拆到单品层和定向层 |
| 4 | 领先率是否用了新客成交口径 | 分子分母必须同源 |
| 5 | 以上都正常 | 转到 [[profit-model]] 查利润与产品竞争力，或 [[customer-asset-ops]] 查人群资产 |
