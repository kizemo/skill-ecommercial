# 爆款评价挖掘 AI Prompt 工具包

**来源**：`taobao-operation` 知识库（智篆商业 少壮老师，第二次线下坐诊 2026-05-10，标准版原文）｜**层级**：L3 工具层｜**版本**：2026.10

把**用户评价**转成三样东西：**用户需求地图**、**爆款产品方向**、**可执行电商策略**。

知识库里现成的第二个「技能包」—— 12 个 Prompt 的完整规格在 `chapters/ch01`，可直接照抄执行。

---

## 一、为什么评价是最被低估的数据源

评价不只是给买家看的。**高价值评价里同时写着：用户的需求、痛点、场景，以及产品当前做不到的地方。**

其中最有价值的一类是**冲突点**：

> **冲突点 = 用户想要 A，但产品只能做到 B**

冲突点是**差异化卖点的核心来源** —— 因为所有竞品都停在 B 上，谁先做到 A，谁就拿到差异化。

## 二、六模块十二 Prompt 总览

| 模块 | Prompt | 核心问题 |
|---|---|---|
| **1. 数据清洗** | P1-P2 | 哪些评价值得分析？ |
| **2. 评价结构化** | P3-P4 | 用户说了什么？ |
| **3. 需求洞察** | P5-P7 | 用户真正想要什么？ |
| **4. 人群拆解** | P8-P9 | 谁在买？为什么买？ |
| **5. 爆款机会** | P10-P11 | 下一个爆款机会在哪？ |
| **6. 商业转化** | P12 | 如何落地执行？ |

**顺序执行，不可跳步。**

---

## 三、评价分级体系（P2 的判据）

| 分数 | 类型 | 内容质量 |
|---|---|---|
| **5 分** | 高价值 | 包含明确需求 + 痛点 + 场景 |
| **4 分** | 中高价值 | 有明确痛点或对比 |
| **3 分** | 中等价值 | 有具体使用反馈 |
| **2 分** | 弱信息 | 仅笼统满意/不满意 |
| **1 分** | 无意义 | 无有效信息 |

> **只有 4 分以上的评价才进入结构化分析。** 低于此阈值 —— 说明该先优化评价收集，而不是硬挖。

## 四、标准执行 SOP（7 步）

| Step | 内容 |
|---|---|
| **Step1** | 导入评价 |
| **Step2** | 执行 Prompt 1-2（清洗 + 筛选） |
| **Step3** | 执行 Prompt 3-4（结构化） |
| **Step4** | 执行 Prompt 5-7（洞察） |
| **Step5** | 执行 Prompt 8-9（人群） |
| **Step6** | 执行 Prompt 10-11（机会） |
| **Step7** | 执行 Prompt 12（商业化） |

---

## 五、三条执行纪律

### 1. 每个 Prompt 单独开一个对话窗口
避免上下文污染 —— 前一步的结论会带着偏见进入下一步的判断。

### 2. 每次使用前加强化指令
在所有 Prompt 前加：
```
当前类目：<类目名>
目标人群：<人群标签>
（例如：血压测量仪 / 老人 / 孕妇）
```

### 3. 冲突点挖掘（P6）是差异化卖点的核心来源
不要跳过 P6 直接做 P10 —— 没有冲突点，产出的"差异化点"通常只是现有卖点的换句话说。

---

## 六、最终产出（必须拿到的 3 个结果）

1. **用户需求地图** — 高频需求 / 痛点 / 场景 TOP10
2. **爆款产品方向** — 5 个基于数据的产品机会
3. **可执行电商策略** — 产品 / 定价 / 内容 / 评价 / 爆款路径

**三样缺一不可。** 只有需求地图没有策略 = 一堆洞察无法落地；只有策略没有需求地图 = 拍脑袋。

## Scope & Limits

- 输入必须是**真实评价文本**。本 skill 不提供评价采集能力（见 `[[visual-material]]` 的安全补单与买家秀，以及 `[[compliance-medical]]` 的合规边界）。
- P12 产出的"引导用户产生哪些评价"涉及平台规则，**必须先过合规检查**再执行。
- 素材给出的是 Prompt 规格与产出要求，**未给出评价样本量下限** —— 样本过少时频次类结论（TOP10）会失真。
- 与 `[[trend-keyword-launch]]` 并行使用：趋势词给"往哪开"，评价挖掘给"为什么买"。
