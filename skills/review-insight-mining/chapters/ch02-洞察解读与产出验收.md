# 第 2 章 · 洞察解读与产出验收

> 本章讲**怎么读结果、怎么判断结果可不可用** —— Prompt 规格本身在 ch01。

---

## 一、六个模块各自要拿到什么

| 模块 | 必须拿到的输出 | 拿不到说明什么 |
|---|---|---|
| **1. 数据清洗** | 保留列表 + 删除数量统计 + 无效评价类型总结 | 样本池本身就是脏的，先解决评价收集 |
| **2. 结构化** | 逐条拆解表 + 关键词分类表 | 拆解维度不全，人群/场景会漏 |
| **3. 需求洞察** | 高频需求/痛点/场景各 TOP10（带频次与人群）+ ≥5 个冲突点 + 未被满足需求清单 | **冲突点是差异化来源**，出不来说明洞察没做深 |
| **4. 人群拆解** | ≥3 类人群画像 + 人群-需求矩阵 | 人群只按年龄性别切，等于没拆 |
| **5. 爆款机会** | 5 个产品机会 + 10 条卖点 + 标题关键词 + 情绪价值 | 机会与洞察之间没有逻辑链 |
| **6. 商业转化** | 产品/定价/内容/评价/爆款路径五段策略 | 停在"洞察"层，没有落地 |

---

## 二、三个关键模块的读法

### P5 高频需求：看频次，也看人群

每个点都要有**数据支撑（出现次数或占比）+ 对应人群**。

**只给排名不给频次 = 没做。** 频次决定了"这是主需求还是长尾抱怨"。

### P6 冲突点：这是整个工具包的价值所在

```
冲突点 = 用户想要 A，但产品只能做到 B
```

| 要素 | 要求 |
|---|---|
| 冲突描述 | A 是什么、B 是什么，说清楚 |
| 涉及人群 | 哪类人最受这个冲突困扰 |
| 当前产品问题 | 现有产品卡在 B 的哪个具体位置 |
| 潜在解决方向 | 怎么做到 A（**方向，不是方案**） |

**为什么这是差异化来源**：所有竞品都停在 B 上 —— 这个冲突是**整个类目共享的痛点**。谁先做到 A，谁就拿到了差异化，而且不需要打价格战。

**至少 5 个**。少于 5 个通常意味着只挖了产品维度，没挖人群与场景维度。

### P9 人群-需求矩阵：横轴需求，纵轴人群

这张矩阵的价值是**看出交叉空白**：
- 某需求所有人群都要，但没有任何人群被专门服务 → 机会
- 某人群的核心需求完全没有产品对应 → 空白市场

## 三、产出验收标准

### 硬性（缺一不可）

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 三结果齐全 | 需求地图 + 爆款方向（≥5 个）+ 可执行策略 |
| 2 | 4 分以上占比 | P2 输出中 ≥4 分的评价占比可接受 |
| 3 | 洞察带数据 | 高频需求每条有频次/占比 |
| 4 | 冲突点 ≥5 | 且每条含人群 + 问题 + 方向 |
| 5 | 人群 ≥3 类 | 每类含需求/痛点/驱动/价格敏感度 |
| 6 | 矩阵完整 | 人群 × 需求双向可读 |
| 7 | 机会可执行 | 每个机会能直接进打样沟通 |
| 8 | 策略五段齐 | 产品/定价/内容/评价/爆款路径 |

### 质量向（不达标要回头补）

| 信号 | 问题 | 回到哪一步 |
|---|---|---|
| 洞察结论全是"用户希望更好"这类空话 | 拆解维度不够 | 回到 P3，重跑结构化 |
| TOP10 的频次差异极小 | 样本量不足，排名无意义 | 补样本，或改为定性结论 |
| 冲突点都是"价格太贵" | 只挖了价格维度 | 回到 P3/P5，补场景与体验维度 |
| 机会之间高度重叠 | 只有一个需求在驱动 | 回到 P7，找未被满足需求 |
| 策略里的价格带只有一个 | 没做人群分层定价 | 回到 P8/P9 |
| 冲突点与机会对不上 | 机会不是从冲突推出来的 | 重跑 P10，强制引用冲突点 |

## 四、常见误判

| 误判 | 后果 | 纠正 |
|---|---|---|
| 把 3 分评价也喂进结构化 | 噪音进入洞察，结论被稀释 | 严格 4 分门槛 |
| 一个窗口跑完 12 个 Prompt | 前一步结论污染后一步判断 | 每步单独开窗口 |
| 跳过 P6 直接做 P10 | "差异化点"变成现有卖点的换句话说 | 强制先出冲突点 |
| 不加强化指令 | 输出泛化到全品类 | 每次加类目 + 目标人群 |
| 把 P12 的"评价策略"直接执行 | 触碰平台规则 | 先过 `[[compliance-medical]]` |
| 用评价洞察代替测款 | 需求成立 ≠ 品能打 | 产出仍要过 `[[selection-testing]]` |

## 五、与其他工具的组合

```
评价挖掘（本工具包）
  ├─→ 需求地图 ──→ 选品方向 ──→ [[selection-testing]] 七维 + 测款
  ├─→ 冲突点   ──→ 差异化卖点 ──→ [[visual-material]] 主图 / [[conversion-optimization]] 详情页
  ├─→ 人群     ──→ 定向设置 ──→ [[customer-asset-ops]]
  ├─→ 价格带   ──→ 定价      ──→ [[pricing-margin]]
  └─→ 爆款路径 ──→ 阶段节奏 ──→ [[hit-product-lifecycle]]

趋势词开款（[[trend-keyword-launch]]）
  └─→ 往哪开  ←── 与评价挖掘并行使用
```

**为什么两个要并行**：趋势词给"**往哪开**"（供给侧的机会窗口），评价挖掘给"**为什么买**"（需求侧的真实动机）。只有前者会追到红海，只有后者会做出没人要的差异化。
