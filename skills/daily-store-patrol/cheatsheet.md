# 速查表 · daily-store-patrol

> 红黄绿一律为**与自身 7 日均值**的相对判定；绝对红线来自知识库并单独列出。
> 数据实测于 2026-10-24（店铺日报截至 10-22、ERP 截至 10-18、万相台截至 10-01）。

---

## 1. 巡店速查卡（贴在工位上）

```
第 0 步  数据新鲜度     —— 三个日期轴对齐了吗
第 1 步  大盘红绿灯     —— 18 指标 + 5 派生指标，比 7 日均值
第 2 步  流量结构       —— 第一次 vs 最后一次，在拉新还是在收割
第 3 步  客户资产       —— 成交三段拆解、回访、复购、粉丝四层
第 4 步  推广计划       —— 四张名单：止损/改造/素材/加投
第 5 步  商品巡检       —— 成本倒挂 > 退货率 > 销量骤降 > 潜力品
第 6 步  出结论         —— ≤5 条行动清单，当天闭环
```

## 2. 四个必查口径（错一个结论就废）

| 项 | 正确 | 错误 | 后果 |
|---|---|---|---|
| **比率单位** | 中位数 >1 判百分数，否则 ×100 | 直接读 | 转化率显示成 0.02% 或 153% |
| **退款率** | ERP `退货金额 ÷ 销售金额`（按订单日期） | `成功退款金额 ÷ 当日支付金额` | 算出 51%，真实值 1.29% |
| **ERP 行类型** | `类型 = '真实'` | 不过滤 | 补单虚增销量、污染退货率 |
| **推广计划归并** | 三张万相台表按 `计划名字` 归并，花费/投产取最大值 | 三张表直接相加或各自成条 | 同一计划被当成两个对象加预算；花费重复计数 |
| **领先率口径** | 客户资产表**金额**口径 | 大盘表人数口径 | 人数口径 7 店全 ≥86%，健泰实际 43.6% 在收割却看着健康 |

## 4. 派生指标算式

| 指标 | 算式 | 数据源 | 判读 |
|---|---|---|---|
| 推广费比 | `(全站+关键词+精准人群+智能场景) ÷ 支付金额` | `core_daily` 同日 | 利润厚度；先验投产真伪 |
| 新客占比 | `支付新买家数 ÷ 支付买家数` | `core_daily` 同日 | <50% = 在跑收割 |
| 老客占比 | `支付老买家数 ÷ 支付买家数` | `core_daily` 同日 | 过高 = 拉新断 |
| 佣金占比 | `淘宝客佣金 ÷ 支付金额` | `core_daily` 同日 | 被动成本，入真实投产 |
| 退款率 | `退货金额 ÷ 销售金额` | ERP 按订单日期 | 大促目标 <5% |
| 真实投产 | `投产 × (1−退款率) × (1−间接成交占比) × 拉新成交` | 知识库公式 | 判断投产真假 |
| 顺逆差 | `单品成交金额占比 − 单品推广花费占比` | 知识库公式 | 花了钱却没成交的品 |

## 5. 流量结构：三种归属原则

| 归属原则 | 回答 | 用于 |
|---|---|---|
| **第一次访问来源** | 买家第一次怎么找到你 | 拉新链路在哪 |
| **最后一次访问来源** | 成交前最后一次从哪来 | 收割链路在哪 |
| 每一次访问来源 | 全部访问 | 总量口径 |

**判据**：某来源「最后一次」的支付买家占比 ÷ 「第一次」≥ 2 ⇒ **在跑收割型定向**。

**机会判据**：某二级来源转化率显著高于店铺均值 ⇒ 该来源加预算（增幅 ≤50%）。

## 6. 重点商品优先级

| 优先级 | 判据 | SQL 核心 | 动作 |
|---|---|---|---|
| **P0** | 成本倒挂 | `sum("销售成本") > sum("商家实收")` | **立刻停投** → `pricing-margin` |
| **P1** | 退货率 ≥ 20% | `sum("退货数量")/sum("销售数量") >= 0.20` | 查质量/描述 → `compliance-medical` |
| **P2** | 销量环比跌 > 50% | 两日对比 | 查断货/下架/处罚/价格 |
| **P3** | 潜力品 | 在 ERP 销售 TOP、但不在万相台推广名单 | 定级 → `sabc-product-tiering` |

## 7. 推广计划四张名单

> **先归并再判名单**：同一个计划会同时落在宝贝/货品、关键词、人群三张表里（同一计划的不同维度滚算，
> 花费与投产一致、新客差 1 以内）。名单按 `计划名字` 归并后出，维度标签合并成「宝贝/货品+关键词」。

| 名单 | 判据 | 动作 |
|---|---|---|
| 🔴 **止损** | 花费>0 且 直接成交=0｜投产<1｜间接 ≥2倍直接 | 降预算 50% → 观察 3 天 → 停 |
| 🟡 **改造** | 投产 ≥1.5 但 成交新客数=0 | 改定向或补拉新计划 |
| 🟡 **素材** | 点击率 < 1% | 换素材（**不要先降价**）→ `visual-material` |
| 🟢 **加投** | 投产 ≥3 且 成交新客数>0 | 加预算，增幅 ≤50% |

## 8. 客户资产判读

| 观察 | 结论 | 动作 |
|---|---|---|
| **金额口径领先率 < 50%** | 成交主要来自老客，在跑收割 | 开拉新计划 → `customer-asset-ops` + `wanxiangtai-wujie` |
| **金额口径领先率 50~70%** | 资源浪费在收割 | 查定向与出价 → `store-diagnosis` |
| 沉睡粉丝 ≫ 活跃粉丝 | 私域未激活 | **今日排召回** |
| 180天复购率 < 3% | 复购弱 | `customer-asset-ops` 复购 |
| 已购客户回访数较自身 7 日均值跌 > 30% | 回访掉头 | 排触达 |
| 金额口径领先率 与 大盘人数口径 差 > 15pp | 两个口径打架 | 标**「口径冲突，需复核」**，别直接下结论 |
| ⚠️ `潜在客户数` 很大 | **平台级累计量，不是本店池子** | **不可**与已购客户数做比值 |

**金额口径领先率** = `新访客&已购支付金额` ÷ 三项支付金额合计（实测 7 店：43.6% ~ 92.0%，有区分度）

## 10. 十个最容易踩的坑

| 坑 | 纠正 |
|---|---|
| 比率字段直接读 | 先做单位自适应归一（ch01 坑 1） |
| 用当日成功退款金额除当日支付金额 | 退款率用 ERP 按订单日期口径（ch01 坑 2） |
| 三个源的数放进一张表比 | 三个日期轴，先对齐再比（ch01 坑 3） |
| ERP 查询忘了过滤「补单」 | 所有 ERP 查询带 `类型='真实'`（ch01 坑 5） |
| 把「第一次访问来源」和「最后一次访问来源」混用 | 三种归属原则不可混用（ch01 坑 6） |
| 三张万相台表的花费相加 / 同一计划列成两条 | 按 `计划名字` 归并，花费取最大值不累加（ch01 坑 7） |
| 查 `customer_assets_2026` 时写了「成交新客占比」 | 这张表没这列，会让整段客户资产变空（ch01 坑 8） |
| 拿 `潜在客户数` 和 `已购客户数` 做比值 | 那是平台级累计量（6,359 万 vs 2.3 万），不可比（ch01 坑 9） |
| 拿人数口径的新客占比当领先率 | 7 店实测全部 ≥86%，无区分度；用金额口径（ch01 坑 10） |

## 11. 脚本速查

```bash
export PGHOST=127.0.0.1 PGPORT=5432 PGUSER=<用户>

python skills/daily-store-patrol/scripts/daily_patrol.py --shop all --out patrol-today.md
python skills/daily-store-patrol/scripts/daily_patrol.py --shop haoyale --date 2026-10-22
```

| 参数 | 说明 |
|---|---|
| `--shop` | `haoyale`/`feite`/`fengshangzhi`/`renhe`/`zhuoguang`/`jiantai`/`darong` 或 `all` |
| `--date` | 统计日期，默认各表最新 |
| `--out` | 输出文件路径 |
| `PATROL_DEBUG=1` | 打印完整错误堆栈 |

**脚本内置已处理的坑**：比率单位自适应归一、退款口径分离、推广费来源分流、补单过滤、归属原则分列、**推广计划按名归并**、**客户资产三段拆解与金额口径领先率**、**口径冲突自动标注**、日期新鲜度提示、查询失败不中断。
