# 术语表 · daily-store-patrol

> 每条标注来源。「库实测」= 2026-10-24 对本机 PostgreSQL 的实际查询；「知识库」= `taobao-operation` 笔记。

**core_daily_2026** — 店铺经营核心日报表，124 列，源文件为生意参谋导出的《店铺经营核心日报表》。含访客/成交/转化/客单价/退款/评分/会员/四项推广花费。7 个淘宝店铺各有一份，按 `stat_date` + `shop_id` 定位。（来源：库实测）

**shop_traffic_source_2026** — 流量来源表，31 列，含三级来源与 `归属原则`。7 店合计约 16 万行。（来源：库实测）

**归属原则** — 流量来源表的归因口径字段，三选一：**第一次访问来源**（买家第一次怎么找到你，拉新链路）／**最后一次访问来源**（成交前最后一次从哪来，收割链路）／**每一次访问来源**（全部访问，总量口径）。三组访客数相同但支付数不同，**混用会得出反向结论**。（来源：库实测）

**customer_assets_2026** — 客户资产表，48 列，含池子（用户数/新访客户数）、成交三段拆解、回访、复购、粉丝四层（总/活跃/沉睡/机会）、会员。源文件为《客户资产_YYYY-MM.xlsx》。**表里混了当日口径、累计口径、平台级口径三类数**（`潜在客户数` 实测 6,359 万 vs 用户数 2.3 万，不可做比值）；**表内没有「成交新客占比」「入会率」「引导访问量」这类列**。（来源：库实测）

**wxt_promotion_baobei_2026 / _keyword_2026 / _audience_2026** — 万相台（无界）三类推广明细表，83-87 列，层级为 场景→计划→单元→（宝贝／词／人群）。`_fullsite_`/`_scene_`/`_unit_` 三张表当前**无数据**。（来源：库实测）

**成交新客数** — 万相台表字段，该计划带来的新客成交人数。是判断"只收割不拉新"的直接依据。（来源：库实测；判读见知识库 `store-diagnosis` 领先率）

**推广花费四项** — `全站推广花费` + `关键词推广花费` + `精准人群推广花费` + `智能场景花费`。**淘宝店铺的推广费用只在这四个字段里**，ERP 侧的 `推广费用` 对淘宝为 NULL。（来源：库实测）

**daily_sku_dd_2026 / daily_store_dd_2026** — ERP 侧日汇总表。`dd` 为日常单，`ys` 为预售单。SKU 版 38 列（含销售/成本/退货/次品/换货），店铺版 25 列（含推广费用/营销费用/投产比）。（来源：库实测）

**类型（真实/补单）** — ERP 日汇总表的行类型枚举。`真实` 是真实成交，`补单` 是补单记录。**所有 ERP 查询必须过滤 `类型='真实'`**，否则销量被虚增、退款率与投产比失真。（来源：库实测；补单相关见知识库 `compliance-medical` 安全补单章节）

**成功退款金额** — `core_daily` 字段，指**当天发生的退款金额**（含历史订单今天退的钱）。**不是当期退款率**，只能看趋势。真实退款率要用 ERP 按订单日期的 `退货金额 ÷ 销售金额`。（来源：库实测）

**当日退款发生额** — 本 skill 对 `成功退款金额` 的称呼，用来避免与"退款率"混淆。（来源：本 skill 命名）

**成本倒挂** — `销售成本 > 商家实收`，即卖一单亏一单。本 skill 的 P0 止损项。（来源：库实测指标定义）

**真实投产** — 投产去掉水分后的值：`投产 × (1−退款率) × (1−间接成交占比) × 拉新成交`。用于判断"投产好"是不是假好。（来源：知识库 `profit-model`）

**领先率** — `新客成交 ÷ 总成交`。四档判定：≥80% 合格线｜70-80% 头部 KA 可接受｜50-70% 资源浪费在收割｜<50% 主要在跑收割｜<30% 拉新链路已断。（来源：知识库 `store-diagnosis`）

**金额口径领先率** — 领先率在库里的可算版本：`新访客&已购支付金额 ÷ 三项支付金额合计`（新客／潜客首购／老客回购）。7 店实测 43.6%~92.0%，有区分度。**大盘表的 `支付新买家数 ÷ 支付买家数` 是人数口径**，7 店实测全部 ≥86%，接近饱和，不适合判拉新/收割。（来源：库实测）

**成交三段拆解** — 客户资产表把当天成交拆成三段：新访客成交（新客）、潜客首购、老客回购。**实测 7 店全部满足：人数三项合计 = `core_daily.支付买家数`，金额三项合计 = `core_daily.支付金额`**，可作为取数正确的交叉对账。（来源：库实测）

**口径冲突，需复核** — 本 skill 的固定标记。当金额口径领先率与大盘人数口径相差 >15 个百分点时显式标注，不直接下结论。**是口径差异，不是数据异常。**（来源：本 skill 定义；判读见知识库 `store-diagnosis`）

**归并（按计划名）** — 同一个推广计划会同时出现在宝贝/货品、关键词、人群三张万相台表里（同一计划的不同维度滚算，花费与投产一致、新客差 1 以内）。巡店清单必须按 `计划名字` 归并，否则同一计划被当成多个可加投对象、同一笔花费被重复计数。（来源：库实测）

**归因切换法** — 用"第一次访问来源"与"最后一次访问来源"的差异，判断投放是在跑拉新还是收割。后者占比远高即为收割型定向。（来源：知识库 `store-diagnosis`）

**间接成交 / 直接成交** — 直接成交＝本次点击带来的成交；间接成交＝本次点击后换别的入口成交。四层分析法判据：**间接成交 = 直接成交 2 倍 ⇒ 该品投放完全无效**。（来源：知识库 `store-diagnosis`）

**红绿灯监控法** — 用红/黄/绿三色跟踪指标完成情况。原则：每部门 ≤3 个关键指标；目的是找问题持续改进，**不直接与绩效考核挂钩**；业务变化快的按周监控、变化慢的按月监控。（来源：知识库 `红绿灯监控法`）

**巡店六步** — 数据新鲜度确认 → 店铺大盘红绿灯 → 流量结构定位 → 客户资产体检 → 推广计划体检 → 商品层巡检 → 出结论。（来源：本 skill 定义，方法论来自知识库 `store-diagnosis` 与工具链 `toolchain-ai`）

**巡店节奏** — 每日必巡（早上 5 分钟）／大促加倍（每 4 小时 1 次）／重点盯爆款（TOP3 专项）。本 skill 把"5 分钟"扩展为完整六步流水线。（来源：知识库 `toolchain-ai`）

**单位自适应归一** — 比率字段在库中可能是百分数（1.53 = 1.53%）也可能是小数（0.0153 = 1.53%）。判定方法：取目标日期 ±3 天窗口的中位数，>1 判百分数，≤1 判小数。（来源：库实测）

**三源三日期轴** — 店铺日报（最新）、ERP（落后约 4 天）、万相台（落后约 3 周）三条独立时间轴。跨源比较必须先对齐日期。（来源：库实测）

**bi.dim_shop** — ERP 侧店铺字典，19 个店，含 `platform`／`finance_shop`／`team_group`（红队/蓝队/其他）。是 taobao 库与 erp 库之间的**店铺对齐键**：`short_name` 对应 schema 名，`shop_name` 对应 `店铺名称`。（来源：库实测）

**重点商品四优先级** — P0 成本倒挂（停投）｜P1 退货率异常（查质量）｜P2 销量骤降（查断货/下架）｜P3 潜力品（有销量无推广，加投候选）。（来源：本 skill 定义）

**四张计划名单** — 止损名单（有花费无直接成交／投产<1／间接≥2倍直接）｜改造名单（投产达标但新客为 0）｜素材名单（点击率<1%）｜加投名单（投产≥3 且带新客）。（来源：本 skill 定义，判据来自知识库）

**放量 ≤50%** — 每次加预算的增幅上限，超过会掉转化率。（来源：知识库 `taobao-ops-playbook`）

**四重对比** — 店铺环比 + 店铺同比 + 同行同层平均 + 同行同层优秀。只看环比会在大盘下跌时误判。（来源：知识库 `toolchain-ai` AI 报告）
