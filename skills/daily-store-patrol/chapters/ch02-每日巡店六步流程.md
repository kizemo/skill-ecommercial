# 第 2 章 · 每日巡店六步流程

> 每步四问：**看什么 / 怎么查 / 怎么判读 / 做什么**。
> SQL 中的中文列名需要双引号；比率字段记得先做单位归一（见 ch01 坑 1）。

---

## 第 0 步 · 数据新鲜度确认（5 分钟，先做完再谈巡店）

**为什么放第一步**：拿旧数据下结论，等于没巡。

### 看什么

七张表的各自最新日期 + 行数。

### 怎么查

```sql
-- 逐表确认（把 <shop> 换成 shop_haoyale 等）
select max(stat_date) from shop_haoyale.core_daily_2026;
select max(stat_date) from shop_haoyale.shop_traffic_source_2026;
select max(stat_date) from shop_haoyale.customer_assets_2026;
select max(stat_date) from shop_haoyale.wxt_promotion_baobei_2026;
select max(stat_date) from shop_haoyale.wxt_promotion_keyword_2026;
select max(stat_date) from shop_haoyale.wxt_promotion_audience_2026;

-- ERP 侧
select max("订单日期") from erp_result.daily_sku_dd_2026;
select max("订单日期") from erp_result.daily_store_dd_2026;
```

### 怎么判读

| 现象 | 结论 |
|---|---|
| 店铺日报 ≥ 今天 − 1 | 正常 |
| 店铺日报落后 ≥ 2 天 | 先查 ETL，别巡店 |
| 万相台落后 3 周左右 | **正常**（实测就是 10-01 vs 10-22），结论标注"截至 X 日" |
| ERP 落后 4 天左右 | **正常** |
| 某表空 | 该维度跳过，别用 0 代替 |

### 做什么

- 数据不到位 → **先修数据**，不做巡店结论
- 数据到位 → 在报告开头写清"各源截至 X 日"

## 第 1 步 · 店铺大盘红绿灯（10 分钟）

### 看什么

18 个核心指标 + 5 个派生指标。

### 怎么查

```sql
-- 当日 + 前一日 + 前 7 日基线
select "访客数","支付金额","支付买家数","支付转化率","客单价","UV价值","跳失率",
       "成功退款金额","支付新买家数","支付老买家数",
       "全站推广花费","关键词推广花费","精准人群推广花费","智能场景花费","淘宝客佣金",
       "描述相符评分","服务态度评分","物流服务评分"
from shop_haoyale.core_daily_2026
where stat_date = '2026-10-22';

select "访客数","支付金额","支付转化率","客单价","UV价值","跳失率"
from shop_haoyale.core_daily_2026
where stat_date > '2026-10-14' and stat_date < '2026-10-22'
order by stat_date desc limit 7;
```

### 怎么判读

按 SKILL.md 第四节的红绿灯规则（相对 7 日均值 + 绝对红线两条线并行）。

**派生指标算式**（全部取同一张表同一天，口径自洽）：

| 指标 | 算式 | 判读 |
|---|---|---|
| 推广费比 | `(全站+关键词+精准人群+智能场景) ÷ 支付金额` | 利润厚度；**先验投产真伪再谈加不加预算** |
| 新客占比 | `支付新买家数 ÷ 支付买家数` | 领先率代理指标；<50% = 在跑收割 |
| 老客占比 | `支付老买家数 ÷ 支付买家数` | 过高 = 拉新链路断 |
| 佣金占比 | `淘宝客佣金 ÷ 支付金额` | 被动成本，计入真实投产 |
| 当日退款发生额 | `成功退款金额` | ⚠️ 只看趋势，**不是退款率**（ch01 坑 2） |

> **注意 UV价值**：金额口径（支付金额 ÷ 访客数，单位元），**不要乘 100**。

### 做什么

- 红灯项逐个记下来，**先归类**（流量问题 / 承接问题 / 成本问题 / 结构问题），再决定找谁
- 转化率与客单价要一起看：转化率跌而客单价涨，多半是价格或结构变化，不是流量问题

## 第 2 步 · 流量结构定位（10 分钟）

### 看什么

每个二级流量来源的访客、支付金额、支付买家、转化率、加购人数 —— **分三种归属原则各看一遍**。

### 怎么查

```sql
select "归属原则","二级流量来源",
       sum("访客数"), sum("支付金额"), sum("支付买家数"), sum("加购人数")
from shop_haoyale.shop_traffic_source_2026
where stat_date = '2026-10-22'
group by 1,2 order by 3 desc nulls last limit 36;
```

### 怎么判读（这是巡店最关键的一步）

**问题在哪一层，用这张表定位**：

| 观察 | 结论 | 下一步 |
|---|---|---|
| 某来源访客涨、支付没涨 | 流量进来了但接不住 | 该来源流量质量差或商品承接差 |
| 某来源访客跌、支付跌 | 流量萎缩 | 查该来源是否被限流/降权 |
| **最后一次访问来源**里「效果广告」支付买家占比 ≫ **第一次访问来源** | **在跑收割型定向** | `store-diagnosis` 归因切换法 |
| 第一次访问来源里付费来源占比高、但新客数低 | 付费买到的不是新客 | 改定向（`wanxiangtai-wujie`） |
| 某二级来源转化率显著高于店铺均值 | **机会项** | 该来源加预算（`keyword-promo`） |
| 搜索流量占比高但转化低 | 搜索承接有问题 | `keyword-promo` + `conversion-optimization` |
| 推荐流量占比 85%+、免费搜索 <5% | 2026 的常态结构 | 不要拿"优化搜索"当万能解（`taobao-ops-playbook`） |

> **归属原则不可混用**（ch01 坑 6）。三组的访客数相同但支付数不同，混用会得出反向结论。

### 做什么

- 圈出**掉得最多的 3 个来源**和**涨得最多的 3 个来源**，分别归因
- 找出**效率最高但量小**的来源 → 列为加投候选

---

## 第 3 步 · 客户资产体检（5 分钟）

### 看什么

池子厚度、成交的三段拆解（新客 / 潜客首购 / 老客回购）、回访是否发生、复购强度、粉丝四层分布。

### 怎么查

```sql
select "用户数","新访客户数","潜在客户新访客户数","已购客户数",
       "已购客户回访数","180天复购率","总粉丝数","活跃粉丝数","沉睡粉丝数","机会粉丝数",
       "新访客&已购支付金额","未购买&购买支付金额","已购&回购支付金额",
       "新访客&已购用户数","未购买&购买用户数","已购&回购用户数"
from shop_haoyale.customer_assets_2026
where stat_date = '2026-10-22';
```

> ⚠️ 这张表**没有** `成交新客占比` / `入会率` / `引导访问量` / `会员成交金额` / `会员首购人数`
> 这些列（它们只存在于 `wxt_promotion_*` 表）。查了会让整条 SQL 报错、客户资产段直接变空。

### 成交三段拆解（这是客户资产最有信息量的一块）

| 分段 | 字段（人数 / 金额） | 含义 |
|---|---|---|
| **新客** | `新访客&已购用户数` / `新访客&已购支付金额` | 第一次来就成交的人 —— 真拉新 |
| **潜客首购** | `未购买&购买用户数` / `未购买&购买支付金额` | 来过没买、这次才买 —— 承接转化 |
| **老客回购** | `已购&回购用户数` / `已购&回购支付金额` | 复购 —— 存量生意 |

**实测对账（7 家店全部吻合）**：人数三项合计 = `core_daily.支付买家数`；
金额三项合计 = `core_daily.支付金额`。所以「金额口径领先率」可以直接用：

```
金额口径领先率 = 新访客&已购支付金额 ÷ 金额三项合计
```

### 怎么判读

| 观察 | 结论 | 动作 |
|---|---|---|
| **金额口径领先率 < 50%** | 成交主要来自老客，在跑收割 | 开拉新计划、查定向（`customer-asset-ops` + `wanxiangtai-wujie`） |
| **金额口径领先率 50~70%** | 资源浪费在收割 | 查定向与出价（`store-diagnosis`） |
| 沉睡粉丝 ≫ 活跃粉丝 | 私域没激活 | **召回机会**（今日就排） |
| `180天复购率` < 3% | 复购弱 | 老客运营（`customer-asset-ops`） |
| 已购客户回访数较自身 7 日均值跌 > 30% | 回访掉头 | 排触达任务 |
| 金额口径领先率与大盘人数口径差 > 15pp | 两个口径打架 | **口径冲突，需复核**，别直接下结论 |
| `潜在客户数` 很大 | ⚠️ **平台级累计量，不是本店池子** | **不可**与已购客户数做比值，别据此判"大量到店未成交" |

### 做什么

- 沉睡粉丝数写进今日行动清单（召回是可立即执行的增量）
- 复购率与大盘的老客金额占比**交叉验证**，两个都指向同一方向才行动
- 回访数用**自身 7 日均值**做相对判定（绝对阈值在所有店都 <1%，没有区分度）

## 第 4 步 · 推广计划体检（15 分钟）

### 看什么

三类万相台推广（宝贝/货品、关键词、人群）**逐计划**的花费、成交、投产、新客。

### 怎么查

```sql
select "计划名字", sum("花费"), sum("直接成交金额"), sum("间接成交金额"),
       sum("成交新客数"), sum("展现量"), sum("点击量")
from shop_haoyale.wxt_promotion_baobei_2026
where stat_date = (select max(stat_date) from shop_haoyale.wxt_promotion_baobei_2026)
group by 1 order by 2 desc nulls last limit 20;
```

关键词表把 `计划名字` 换成 `计划名字` + `词名字/词包名字` + `宝贝名称`；人群表加 `人群名字`。

### 怎么判读

| 判读 | 口径 | 含义 |
|---|---|---|
| 🔴 有花费无直接成交 | `花费>0` 且 `直接成交金额=0` | 白花钱 |
| 🔴 间接 ≥ 2 倍直接 | `间接成交金额 ÷ 直接成交金额 ≥ 2` | **知识库红线：该品投放完全无效** |
| 🔴 投产 < 1 | `总成交金额 ÷ 花费 < 1` | 亏 |
| 🟡 只收割不拉新 | 投产 ≥1.5 但 `成交新客数=0` | 需要补拉新计划 |
| 🟡 点击率 < 1% | `点击量 ÷ 展现量 < 1%` | 素材问题，不是投放问题 |
| 🟢 投产 ≥3 且带新客 | — | 赢家，加预算（增幅 ≤50%） |
| 花费 0 但有成交 | — | 自然成交，不占预算 |

> **投产比口径**：脚本用（直接+间接）÷ 花费近似；平台自带 `投入产出比` 字段口径可能不同，**最终以平台字段为准**。

### 做什么

- 产出两份名单：**今日要动的计划**（🔴）与**今日可加的计划**（🟢）
- 🔴 计划**先降预算不停投**（放量增幅 ≤50%，不要一步砍到 0）
- 🟡 计划查素材与定向（`visual-material` / `wanxiangtai-wujie`）

## 第 5 步 · 商品层巡检（15 分钟）

### 看什么

SKU 级的销售、退货、成本。

### 怎么查

```sql
select "商品编码", sum("销售金额"), sum("销售数量"), sum("退货数量"),
       sum("退货金额"), sum("商家实收"), sum("销售成本")
from erp_result.daily_sku_dd_2026
where "订单日期" = '2026-10-18' and "类型" = '真实'
group by 1 order by 2 desc nulls last limit 30;
```

### 怎么判读

| 判读 | 口径 | 动作 |
|---|---|---|
| 🔴 **成本倒挂** | `销售成本 ÷ 商家实收 > 100%` | 卖一单亏一单 → **立刻停投**，再查定价与成本（`pricing-margin`） |
| 🔴 退货率过高 | `退货数量 ÷ 销售数量 ≥ 20%` | 查质量/描述/预期差（`compliance-medical` + `conversion-optimization`） |
| 🔴 销量骤降 | 销售金额环比跌 >50% 且昨日有量 | 查断货/下架/权重/价格 |
| 🟡 有金额无件数 | `销售金额>0` 且 `销售数量=0` | 数据异常，多为赠品或全额退款 |
| 🟡 次品数量 > 0 | `次品数量` | 质量事故，进售后流程 |
| 🟢 有销量无推广 | 卖得动但没投 | **潜力品**，加投候选 |

### 做什么

- 成本倒挂与高退货率商品 → 进今日行动清单第一行（止损优先）
- 潜力品 → 交给 `sabc-product-tiering` 定级

## 第 6 步 · 出结论（10 分钟）

### 看什么

把前五步的发现收敛成三样东西。

### 怎么写

**① 红绿灯汇总表**（只保留有方向的指标，中性指标不列）

```
| 指标 | 当日 | 7日均值 | 灯 |
```

**② 今日行动清单**（每条必须落到"谁 + 做什么"）

```
- 🔴 支付转化率 1.53%（7日均值 1.98%，-22.8%）→ 转 `conversion-optimization` 查主图与详情页
- 🔴 推广计划 · 宝贝推广 · 关键词推广_20260302_足弓拖鞋A1拉新（花费 38,035.62）→ 有花费无直接成交
- 🟢 沉睡粉丝 9,049 + 复购率 2.15% → 今日排召回
```

**③ 机会清单**（找增量，不只找错）

```
- 费比 21.84% 低于 7 日均值且投产达标 → 回收预算加投赢家
- 「手淘推荐」转化率 0.31% 显著高于店铺均值 0.15% → 该来源加预算
```

### 怎么判读（收尾自检）

- 每条红灯都归到一类（流量/承接/成本/结构/合规）了吗？没归类的先归类再派活
- 每个红灯都有**下一步动作和负责人**吗？没有就不算巡店完成
- 行动清单**不超过 5 条**吗？（红绿灯监控法：抓主要矛盾，不是列清单）
- 有没有把**不同日期的数混在一张表**比较？（ch01 坑 3）

### 做什么

- 行动清单进当天的待办，**红灯项当天必须闭环**
- 巡店结论存档，供周检做趋势对比（ch05）
