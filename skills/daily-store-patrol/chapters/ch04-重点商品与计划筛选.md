## 一、重点商品：四个优先级

排序规则：**止损优先 → 风险预警 → 异动排查 → 加投候选**。

### P0 · 成本倒挂（立刻停投）

```sql
select "商品编码", sum("销售金额"), sum("商家实收"), sum("销售成本"),
       round((sum("销售成本")/nullif(sum("商家实收"),0)*100)::numeric,2) as 成本占实收
from erp_result.daily_sku_dd_2026
where "订单日期" = '2026-10-18' and "类型" = '真实'
group by 1
having sum("销售成本") > sum("商家实收")
order by 3 desc;
```

**判据**：`销售成本 > 商家实收` → 卖一单亏一单。
**动作**：停投 → `pricing-margin` 倒推活动空间与最低价 → 查是否有未同步的降价活动。

### P1 · 退货率异常

```sql
select "商品编码", sum("销售数量"), sum("退货数量"), sum("退货金额"),
       round((sum("退货数量")/nullif(sum("销售数量"),0)*100)::numeric,2) as 退货率
from erp_result.daily_sku_dd_2026
where "订单日期" = '2026-10-18' and "类型" = '真实'
group by 1
having sum("销售数量") > 0
   and sum("退货数量")/nullif(sum("销售数量"),0) >= 0.20
order by 5 desc;
```

**阈值来源**：知识库大促复盘目标退款率 **< 5%**；日常单日 20% 视为异常。
**动作**：查售后类型分布 → 医械类目过 `compliance-medical`。

### P2 · 销量骤降

```sql
with d as (
  select "商品编码", "订单日期", sum("销售金额") as amt
  from erp_result.daily_sku_dd_2026
  where "类型" = '真实' and "订单日期" between '2026-10-17' and '2026-10-18'
  group by 1,2
), piv as (
  select "商品编码",
         sum(case when "订单日期"='2026-10-18' then amt else 0 end) as d2,
         sum(case when "订单日期"='2026-10-17' then amt else 0 end) as d1
  from d group by 1
)
select "商品编码", d1 as 昨日, d2 as 今日,
       round((d2-d1)/nullif(d1,0)*100,2) as 环比
from piv
where d1 > 0 and d2/d1 < 0.5
order by d1 desc;
```

**动作**：查库存（断货）、是否下架、是否被处罚、价格是否变动。

### P3 · 潜力品（有销量无推广）

**为什么重要**：巡店不只止损，还要找增量。自然能卖却没有推广计划的商品，是最便宜的增量。

```sql
-- 商品层销售 TOP
select "商品编码", sum("销售金额"), sum("销售数量")
from erp_result.daily_sku_dd_2026
where "订单日期" = '2026-10-18' and "类型" = '真实'
group by 1 order by 2 desc limit 20;
```

再拿这个名单去万相台三表里查有没有对应计划：

```sql
-- 关键词推广里出现过的宝贝
select distinct "宝贝ID", "宝贝名称"
from shop_haoyale.wxt_promotion_keyword_2026
where stat_date = (select max(stat_date) from shop_haoyale.wxt_promotion_keyword_2026);

-- 宝贝推广里出现过的主体
select distinct "主体ID", "主体名称"
from shop_haoyale.wxt_promotion_baobei_2026
where stat_date = (select max(stat_date) from shop_haoyale.wxt_promotion_baobei_2026);
```

**不在推广名单里、但销售榜前列的商品** → 潜力品。

**动作**：`sabc-product-tiering` 定级（B 级动销 / A 级利润），`wanxiangtai-wujie` 建计划。

> ⚠️ **无法直接 join**：ERP 的 `商品编码` 与万相台的 `宝贝ID`/`主体ID` **不是同一套编码**（ERP 是商家内部编码，万相台是平台宝贝 ID）。
> 实际做法：用**商品名称**（`item_name` / `主体名称` / `宝贝名称`）做人工映射，或在 `jst_dw` 库用 `jst_dim_sku` 做一次编码对齐。
> **编码映射关系本轮未验证**，落地前先人工核几个样本。

## 二、重点推广计划

### 2.1 逐计划体检（脚本已实现）

按 `计划名字` 聚合三张表：

```sql
select "计划名字", sum("展现量"), sum("点击量"), sum("花费"),
       sum("直接成交金额"), sum("间接成交金额"), sum("成交新客数"),
       round(((sum("直接成交金额")+sum("间接成交金额"))/nullif(sum("花费"),0))::numeric,2) as 近似投产,
       round((sum("点击量")/nullif(sum("展现量"),0)*100)::numeric,2) as 点击率
from shop_haoyale.wxt_promotion_baobei_2026
where stat_date = (select max(stat_date) from shop_haoyale.wxt_promotion_baobei_2026)
group by 1
order by 4 desc nulls last;
```

> ⚠️ 这段 SQL 要对**三张表各跑一次**（宝贝/货品、关键词、人群）。同一个计划会同时出现在多张表里
> （同一计划的不同维度滚算，花费与投产一致、新客数差 1 以内）⇒
> **三张表的花费不能相加**，下面的四张名单必须**按计划名归并**后判定，
> 否则同一个计划会被列成多个对象、并让花费重复计数。详见 ch01 坑 7。

### 2.2 四张名单（今天要动的）

> 四张名单都建立在"归并后的逐计划体检表"上。归并规则：维度标签合并成「宝贝/货品+关键词」，
> 花费/投产取最大值（不累加同一笔钱），新客取最大值。

| 名单 | 判据 | 动作 |
|---|---|---|
| **止损名单** | `花费>0` 且 `直接成交金额=0`；或 近似投产 < 1；或 `间接成交金额 ≥ 2×直接成交金额` | 降预算 50% → 观察 3 天 → 停 |
| **改造名单** | 投产达标但 `成交新客数=0` | 改定向或补拉新计划 |
| **素材名单** | 点击率 < 1% | 换素材（`visual-material`），**不要先降价** |
| **加投名单** | 近似投产 ≥ 3 且 `成交新客数>0` | 加预算，**增幅 ≤50%** |

### 2.3 单计划下钻（拿到"为什么"）

```sql
-- 关键词推广：哪个词烧钱没成交
select "词名字/词包名字", "宝贝名称", "展现量","点击量","花费",
       "直接成交金额","间接成交金额","成交新客数"
from shop_haoyale.wxt_promotion_keyword_2026
where stat_date = '2026-10-01' and "计划名字" = '关键词推广_20260302_足弓拖鞋A1拉新'
order by "花费" desc nulls last limit 20;

-- 人群推广：哪个人群包在收割
select "计划名字","人群名字","花费","直接成交金额","间接成交金额","成交新客数","引导访问潜客数"
from shop_haoyale.wxt_promotion_audience_2026
where stat_date = '2026-10-01'
order by "花费" desc nulls last limit 20;
```

**下钻目的**：把"计划有问题"细化成"**哪个词/哪个宝贝/哪个人群**有问题" —— 只有细到这一层，才能派具体动作。

## 三、重点人群与流量来源

### 3.1 人群包重点

| 名单 | 判据 | 动作 |
|---|---|---|
| **拉新名单** | `成交新客数 > 0` 且 投产 ≥ 3 | 加预算 |
| **收割名单** | `成交新客数 = 0` 但有成交 | 保留但监控；长期改定向 |
| **无效名单** | `花费 > 0` 且 全部成交为 0 | 停 |
| **潜客名单** | `引导访问潜客数` 高、`入会量` 低 | 人群包没转成会员（`customer-asset-ops`） |

### 3.2 流量来源重点

```sql
-- 各二级来源的效率排序（找加投机会）
select "二级流量来源",
       sum("访客数") as 访客,
       sum("支付金额") as 支付,
       round((sum("支付买家数")/nullif(sum("访客数"),0)*100)::numeric,2) as 转化率,
       round((sum("支付金额")/nullif(sum("支付买家数"),0))::numeric,2) as uv价值
from shop_haoyale.shop_traffic_source_2026
where stat_date = '2026-10-22' and "归属原则" = '每一次访问来源'
group by 1
order by 5 desc nulls last;
```

**重点关注两类**：
1. **效率高但量小** → 加投候选（机会）
2. **量��但效率极低** → 降预算或改承接（止损）

## 四、把名单变成行动

一个合格的"重点关注名单"必须包含四列，缺一不可：

| 列 | 举例 |
|---|---|
| **对象** | 商品编码 / 计划名字 / 人群名字 / 二级来源 |
| **问题** | 成本倒挂 / 有花费无直接成交 / 退货率 32% / 点击率 0.8% |
| **证据** | 具体数字（花费 38,035.62、投产 0.7、退货率 32%） |
| **动作 + 归口** | 降预算 50%，3 天后复核 → `wanxiangtai-wujie` |

**只有"问题"没有"证据"的名单不要执行** —— 巡店的每一条都要能被人复核。
