# ch09 · 推广目标制定与红绿灯判定（从数据到报表）

> 来源：智篆商业·老草老师《基于人群资产的淘天运营方法4：多端数据融合调优》§2.3(3)(4)、§3.1、§3.2、§3.3、§4；《推广红绿灯》Excel 模板 V3（`参数!F1` =「根据智篆老草推广红绿灯表格制作」）逐格反推；[[profit-model]] 的利润公式与盈亏平衡投产比；本机 PostgreSQL 实测（7 家淘宝店 × 2026-01 ~ 2026-10）

**这一章补上 ch06 缺的那一块：目标从哪来。**

ch06 给了判定规则和四个场景，但红绿灯的输入——**目标投产比**和**目标费比**——在那里是「人工设定」的值。这一章讲三件事：**目标怎么用历史数据算出来**、**指标口径怎么对齐**、**怎么从数据直接生成红绿灯报表**。

---

## 一、红绿灯判定的输入与九种组合

判定规则本身来自课程原文（§3.1），两轴各三色：

| 指标 | 🟢 绿 | 🟡 黄 | 🔴 红 |
|---|---|---|---|
| **投产（ROI）** | 实际 ROI ≥ 目标 ROI | 目标 ROI × 0.8 ≤ 实际 ROI < 目标 ROI | 实际 ROI < 目标 ROI × 0.8 |
| **费比** | 实际费比 ≤ 目标费比 | 目标费比 < 实际费比 ≤ 目标费比 × 1.2 | 实际费比 > 目标费比 × 1.2 |

两轴组合有九种，但原文只给了四个场景（§3.2）。**黄灯参与的三种组合和「投产红 + 费比黄」原文没写** —— 补齐时按原文的总原则（§4.1「绿灯加、红灯减、黄灯观望优化」，「每次调整预算幅度不超过 30%」）和 §3.3（「连续 3 天黄灯」立即调整）推导，并在下表里标出哪些是原文、哪些是本技能的合成规则：

| 投产 | 费比 | 场景 | 动作 | 出处 |
|---|---|---|---|---|
| 绿 | 绿 | 双绿 | 加预算 20%-30%，系列总增幅 ≤30% | 原文场景1 + §4.2 |
| 绿 | 红 | 投产绿/费比红 | 查退款率 >30% 与间接成交占比 >50%；减 30%-50% 预算 | 原文场景2 |
| 红 | 绿 | 投产红/费比绿 | 查免费流量占比 >70%、推广日预算 <500、拉新占比 >80%；必要时加收割预算 | 原文场景3 |
| 红 | 红 | 双红 | 立即减预算 50%-80% 或暂停，优化后小预算重启 | 原文场景4 |
| 绿/黄 | 黄 | 投产绿/费比黄、投产黄/费比绿、双黄 | 黄灯观望优化；连续 3 天黄灯再调整，单次幅度 ≤30% | 依 §4.1 + §3.3 **合成** |
| 黄 | 红 | 投产黄/费比红 | 按费比红灯侧处置：查退款率与间接成交占比；减 30%-50% 预算 | 依原文场景2 的**费比红灯侧**合成 |
| 红 | 黄 | ⚠️ 混合档：投产红/费比黄 | 按投产红灯侧排查；预算单次调整 ≤30%，不直接套用双红的 50%-80% | **脚本合成规则**，原文四场景未覆盖 |

**总灯 = 两轴取更差的一盏** —— 这同样是合成规则：原文是按场景分别决策，从未定义「单灯」。用的时候把「投产灯/费比灯」一起看，总灯只用来排序。

## 二、11 项指标口径（与模板逐格反推一致）

模板 V3 的「上月数据 / 本月数据」两张表把这 11 个指标都列成了列。**把模板自己算出来的值代回公式，11 项全部吻合（误差 < 1e-6）**，于是口径被反推钉死：

| 指标 | 公式 | 备注 |
|---|---|---|
| GSV（净成交） | GMV − 退款金额 | |
| 退款率 | 退款金额 ÷ GMV | |
| 客单价 | **GMV ÷ 支付人数** | 是毛口径，不是 GSV 口径 |
| 转化率 | 支付人数 ÷ 访客数 | |
| 推广费比 | 推广花费 ÷ GMV | 毛口径 |
| **去退推广费比** | 推广花费 ÷ GSV | 净口径，与 ch02「系列去推费比」一致 |
| 投产比 ROI | 推广成交金额 ÷ 推广花费 | 分子含直接 + 间接成交 |
| 推广成交占比 | 推广成交金额 ÷ GMV | |
| 间接成交占比 | 间接成交金额 ÷ 推广成交金额 | 表里只给占比，金额要乘回来 |
| 推广点击单价 | 推广花费 ÷ 推广点击量 | |
| 平均访客成本 | 推广花费 ÷ 访客数 | |

**两条不能混的规矩**：
1. **客单价是毛口径**（GMV ÷ 支付人数）。用它推净成交规模会高估。
2. **费比有两个分母**：费比（÷GMV）与去退推广费比（÷GSV）。**红绿灯的费比轴用去退推广费比**（模板的 W 列、ch02 的「商家应优先使用」口径），因为退款率高的货用毛口径费比会假装很健康。

> **比率一律现算，不读表里预存的比率列。** 模板里的比率列是上一次算好写死的，一旦口径变了整张表跟着错。汇总时也要用汇总后的量重算比率，不能平均各行比率。

## 三、目标制定：双轨取严

红绿灯是**相对目标**的判定，目标错了灯就全错。模板的目标链是**纯历史平移**——「预估目标」行的目标投产比直接等于上月投产比、目标费比直接等于上月去退费比（读模板公式 `U6`/`W6` 确认）。也就是说：**只要利润结构没变，目标就永远等于历史，红绿灯永远「照抄上月」。**

所以补一条**利润约束**轨道，两轨取严：

### 轨道 A · 利润约束（底线，回答「再差也不能差到哪」）

| 目标 | 公式 | 出处 |
|---|---|---|
| 目标投产比**下限** | `1 ÷ [毛利率 × (1 − 退款率)]` | [[profit-model]] 的盈亏平衡投产比，**实盘取更严的一版** |
| 目标去退费比**上限** | `(毛利率 − 运营成本率) ÷ (1 − 退款率)` | **由 profit-model 利润公式推导，原文没有直接给出这个公式** |

去退费比上限的来历：`利润 = 销售额 × 毛利率 − 运营成本 − 推广费用 ≥ 0`，把 `运营成本率` 定义在销售额上、`推广费比` 定义在 GSV 上，整理即得上式。**前提是运营成本率按销售额口径估**（平台扣点是销售额比例，人工与仓储是半固定，用比例估是近似）——这个近似要自己认。

### 轨道 B · 历史基线（可达，回答「照这个做能不能做到」）

| 目标 | 公式 | 出处 |
|---|---|---|
| 目标 GSV（净） | 上期 GSV | 模板 `F6` |
| 目标 GMV（毛） | 上期 GSV ÷ (1 − 上期退款率) | 模板 `E6 = F6/(1−H6)` |
| 目标投产比参考 | 上期实际投产比 | 模板 `U6` |
| 目标去退费比参考 | 上期实际去退推广费比 | 模板 `W6` |

### 取严规则

```
目标投产比   = max(利润约束下限, 上期实际投产比)      ← 投产要高的那个更难，取严
目标去退费比 = min(利润约束上限, 上期实际去退费比)    ← 费比要低的那个更难，取严
目标推广花费 = 目标 GSV（净） × 目标去退费比
目标推广成交金额 = 目标 GMV（毛） × 上期推广成交占比
目标流量     = 目标 GMV（毛） ÷ (上期客单价 × 上期转化率)
目标点击量   = 目标推广花费 ÷ 上期推广点击单价
目标进度     = 目标值 ÷ 目标周期总天数 × 已过天数
```

> ⚠️ **毛净不能混用**：推广费比的分母是 GSV（净），所以**目标推广花费必须用目标 GSV（净）乘目标去退费比**。拿毛 GMV 乘净费比会把目标花费高估（模板 `N6 = F6×W6` 用的是上期 GSV，不是目标 GMV）。

> ⚠️ **口径冲突，需复核**：课程原文 §2.3(3) 的目标拆解写「花费目标 = 总成交目标 × 目标费比」，其中总成交目标是**毛**的（示例：净成交 15 万 ÷ (1−50%) = 30 万，30 万 × 20% = 6 万）。而模板「预估目标」行用的是**净**口径（上期 GSV × 上期去退费比）。同一个「目标费比」，两处乘的基数不同。本技能按模板口径（净）执行，因为红绿灯费比轴用的就是去退推广费比。

## 四、数据通道与能力边界

**商品级红绿灯必须走 Excel 通道，PG 通道只能到店铺级和计划级** —— 这不是取舍，是数据现实：

| 要什么 | Excel 通道 | PG 通道 |
|---|---|---|
| 商品级 GMV / 访客 / 转化率 / 退款率 | ✅ 生意参谋商品明细 | ❌ `core_daily` 是店铺级；ERP 的 `daily_sku_dd_2026`「商品编码」是 ERP 内部码，与淘宝商品 ID 对不上 |
| 商品级推广花费与成交 | ✅ 万相台商品报表 | ⚠️ `wxt_promotion_baobei` 的主体 ID 是商品 ID，但成交侧无同粒度数据，join 不上 |
| 系列/品类维度 | ⚠️ 依赖「宝贝清单」的品类名称（见坑二） | ❌ 无货品成长阶段、无类目 |
| 店铺级 + 计划级 | — | ✅ `core_daily_2026` + `wxt_promotion_*` + ERP |

**PG 通道实测踩到的五个坑**（都在 `scripts/red_green_report.py` 的 `pg_load_shop()` 注释里）：

1. **日期列是 `stat_date`**，不是「日期」—— 万相台表里「日期」列整列是 NULL，按它过滤会**静默返回 0 行**。
2. **万相台是月度快照表** —— `stat_date` 每月只有一个值（实测都是当月 1 号）。按任意日期区间过滤会静默返回 0 行，**只能按自然月取**。
3. **万相台三张表是同一批计划的不同维度视图，不能相加** —— 关键词表、人群表里的计划大多也在宝贝表里。实测相加会把花费算成两倍（宝贝表 330,701 vs 三表相加 670,818）。归并规则：按计划 ID 去重，花费/投产取最大值不累加（同 [[daily-store-patrol]] ch01 坑 7）。
4. **`core_daily` 的「成功退款金额」是当天发生额**（含历史订单退款），拿它除支付金额得到的不是退款率。真实退款率要用 ERP 按**订单日期**的「退货金额」（`erp_result.daily_store_dd_2026`，`类型='真实'`）。
5. **ERP 的「推广费用」一个月只有 1 天有值**（月末快照），按天 sum 会错。推广花费要用 `core_daily` 四项逐日相加。

## 五、模板自身的三个坑

用真实模板（智篆老草推广红绿灯表格 V3）跑过一轮，这三个坑不踩就会算错：

**坑一 · 大盘行 ≠ 明细逐行相加。**
明细区里藏着一行标签也是「(空白)」的**差额行**，末尾还有一行「总计」。实测：
```
大盘行 = 明细合计 + 差额行     ← 两期、8 个量纲逐列成立
```
访客数差 2.3%、推广花费差 0.37%，**用明细合计当大盘，投产比与费比会算偏**。大盘必须取模板自己的汇总行；差额行对不上就说明取数或导出有遗漏。

**坑二 · 「宝贝清单」的品类名称和价格带层级没填。**
空的这两列会让模板「系列汇总-红绿灯」页整页取到 0（它按 `类目[品类名称]` 取数）。本次实测 597 个宝贝的「货品成长阶段」全填、「品类名称」全空 —— 所以**能用的分组维度是货品成长阶段，不是系列/品类**。

**坑三 · 两个「日均 GMV」不同义。**
「上月日均GMV」是**整月**日均（8 月 31 天），「本月日均GMV」是**已过天数**日均（数据截止 9/25 = 25 天）。拿本期日均乘 30 天会高估目标。

## 六、脚本：把上面这套变成可执行报表

`skills/domain-growth-ops/scripts/red_green_report.py` 实现本章全部公式，两条通道一个脚本：

```powershell
# 商品/系列级（Excel 通道）
python scripts\red_green_report.py --input 推广红绿灯_2026-09.xlsx `
  --gross-margin 0.30 --opex-rate 0.05 --period-days 30 `
  --out-md 报表.md --out-csv 明细.csv --out-xlsx 报表.xlsx

# 店铺/计划级（PG 通道，口令走 .pgpass / PGPASSWORD，脚本不内置任何账号）
python scripts\red_green_report.py --pg-shop all --opex-rate 0.05 --out-md 店铺红绿灯.md

# 自检（45 项断言，含造坏数据验校验有牙）
python scripts\red_green_report.py --self-test
```

产物三件套：
- **Markdown 报表**：目标双轨表 → 大盘红绿灯 → **口径对账表**（大盘 vs 明细合计 vs 差额行）→ 分组红绿灯 → 单品明细。
- **CSV 明细**：逐商品的全部指标与灯。
- **Excel 报表（活公式）**：五页 —— `目标假设`（蓝字可改，改完全表重算）、`原始数据`、`单品报表`、`分组汇总`、`口径校验`（公式自检项）。派生值一律写成活公式，不写死数。

## 七、实盘演练：这套东西跑出来的结果

用一份真实模板（智篆老草推广红绿灯表格 V3，2026-09）+ 本机 PG 实测交叉验证：

| 验证项 | 结果 |
|---|---|
| 11 项指标公式逐格反推 | 11/11 吻合，误差 < 1e-6 |
| 大盘行 = 明细合计 + 差额行 | 两期 × 8 个量纲全部成立 |
| 宝贝表花费 = `core_daily` 四项 | 10 个月里 8 个月完全相等，其余月份差 < 0.05% |
| 万相台三表相加 vs 真实花费 | 670,818 vs 330,701 —— **相加是错的** |
| Excel 活公式 vs Python 实算 | 目标投产比 / 目标去退费比 / 目标 GSV / 目标 GMV / 目标花费 **零不一致** |

该店 2026-09 的判定结果：投产比 3.014（目标 5.740，红）｜去退费比 35.54%（目标 33.06%，黄）｜总灯红｜场景「投产红/费比黄」。

**目标投产比 5.740 是利润约束给的下限**（毛利率 30%、当期退款率 41.93% ⇒ `1÷(0.30×(1−0.4193))`），不是上期的 3.347 —— 这就是「双轨取严」和「照抄上月」的分水岭。

## 避坑指南

| # | 坑 | 破法 |
|---|---|---|
| 1 | 目标永远照抄上月 | 双轨取严：利润约束给底线，历史基线给可达 |
| 2 | 用毛 GMV 乘净费比 | 目标花费 = 目标 GSV（净）× 目标去退费比 |
| 3 | 大盘用明细相加 | 取模板自己的汇总行，差额行单独立账对账 |
| 4 | 客单价用了 GSV 口径 | 客单价 = GMV ÷ 支付人数（毛口径） |
| 5 | 汇总时平均各行比率 | 用汇总后的量重算比率 |
| 6 | 万相台三表相加 | 按计划 ID 去重，花费/投产取最大值不累加 |
| 7 | 万相台按任意日期区间查 | 它是月度快照，只能按自然月取 |
| 8 | 用当天退款发生额算退款率 | 用 ERP 按订单日期的退货金额 |
| 9 | 品类名称没填还想要系列维度 | 先补「宝贝清单」的品类名称与价格带层级 |
| 10 | 两套红绿灯口径混用 | 巡店红绿灯是**相对**（自身 7 日均值），推广红绿灯是**绝对**（目标 ROI / 目标费比） |
