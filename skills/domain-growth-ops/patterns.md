# patterns · 全域增长操盘体系

可复用的操作套路。每条给出**何时用 / 怎么做 / 代价与风险**。数字均来自知识库原文，未覆盖处标注为「素材未覆盖，未验证」。

---

## 1. 系列化核算：把货打包花"一包钱"

**何时用**
单个宝贝费比超标但你怀疑它其实在带流量；或全店费比忽高忽低说不清问题出在哪。

**怎么做**

1. 把主力商品按**心智匹配度**梳理成一个个 SAB 货盘（耳钉与耳圈不能同盘；日系门帘不能延伸到中式门帘）
2. 按系列分配月度目标
3. 按天跟进每个系列的费比 → 超标扣预算；没超标**应该花出去**
4. 打包核算底线（如投产 1:3）→ 这个宝贝 1:8 说明**花少了还要多花**，那个 1:14 减预算投产就回来
5. 目标：费比拉到可接受极限，**把花费绝对值最大化**

**代价/风险**
需要先把货盘梳理对（一次成本高，但一劳永逸）；归因漂移会让两次下载的同一份数据对不上，务必同一时间点下载。

## 2. 推广红绿灯四场景决策

**何时用**
每天例行巡检之后，决定今天的钱往哪动。

**怎么做**
先按两轴三色判定（投产绿 ≥ 目标 / 黄 ≥ 目标×0.8 / 红 < 目标×0.8；费比绿 ≤ 目标 / 黄 ≤ 目标×1.2 / 红 > 目标×1.2），再落到四场景：

| 场景 | 动作 |
|---|---|
| 双绿 | 加预算 20%-30%，系列总增幅 ≤ 30% |
| 投产绿 + 费比红 | 查退款率与间接占比；单品减 30%-50%；不盲目加钱 |
| 投产红 + 费比绿 | 观察优化；必要时加收割预算 |
| 双红 | 减 50%-80% 或暂停，优化后重启 |

**代价/风险**
样本不足时（日预算 < 500 元 或 推广天数 < 7 天）不要判红判绿，走观望：维持预算、优化细节、监控 7-10 天。

## 3. Gap 公式：把"还能加多少"算成数字

**何时用**
想加预算但不敢拍脑袋定加多少。

**怎么做**

```
每日可增加花费 = (过去 N 天平均每天花费 ÷ 当前去退费比) × 去退费比 Gap
累计 Gap      = 历史可支配推广花费 ÷ N 天
合计调整      = 每日可增加花费 + 累计 Gap
```
实测样例：241,465 × 0.42% = 1,014.15；日均 44,865÷6 = 7,477.5；7,477.5 ÷ 18.52% × 0.42% = 169.58；累计 1,014.15÷24 = 42.26；**合计 211.84**。

**代价/风险**
依赖去退费比和 Gap 口径，跨系列不可直接比较；本质是"今天的 Gap + 历史的累积 Gap"两项叠加，别只算其中一项。

## 4. 赛马：资源有限时挑黑马

**何时用**
一批新测试链接各给 500 元日预算，三天后要留哪些；或两个链接费比相近要选一个追加预算。

**怎么做**

- **法则一 相同花费比费比**：A 花 3000 费比 15% / B 花 4500 费比 35% / C 花 3500 费比 20% → A 是黑马（消耗更低且费比极低）
- **法则二 相同费比比花费规模**：D 花 5 万费比 20% / E 花 1 万费比 20% → D 潜力远大于 E（体量 5 倍仍同效率，未达边际效应临界点），追加大额预算优先选 D

**代价/风险**
横向比较必须同一时间周期、同一流量环境；否则测的是流量运气不是货。

## 5. 引潜比诊断：判断一个计划是收割还是拉新

**何时用**
投产看着不错但流量质量在下滑；或者想判断该给哪个计划加钱。

**怎么做**
查计划的**引导访问潜客占比**——20% → AI 收割；60% → O 熟客拉新；85% → O 新客拉新；30% 几 = 拉新型；90% 多 = 收割型；3% = 专门看收割不拉新。

**代价/风险**
**最大陷阱是只看左边的数（投产），不看右边的数（引潜比）** → 投入越多，流量质量越差。

## 6. 心智匹配拆货盘

**何时用**
货盘看起来很厚但间接成交很少；或一个大流量款带不动其它宝贝。

**怎么做**
找出**品类核心决策心智要素**（羽毛球服→颜色+领型；耳饰→尺寸/风格/元素；内衣→功能/杯型/颜色/元素；家纺→花型/颜色/风格），按要素拆成独立货盘，**每个货盘有独立 SAB**。同一盘货的图最关键的不是点击率，而是**点击用户的心智**。

**代价/风险**
拆得太细会摊薄单个货盘的厚度，货盘厚度的真实构成是**有效宝贝数量 × 心智匹配度**——69 个有效抱团宝贝远胜 1000 个零散常微品。

## 7. 左侧拉新两步验证

**何时用**
左侧拉新计划投了一周，报表 ROI 接近零，不知道该留还是该停。

**怎么做**

1. **类目内后链路成交占比（一票否决）**：达摩盘自定义圈人 → 选"万象台无界版回流再营销"标签、勾选所有场景、用"自定义计划"筛出计划 ID → 圈出过去 30 天点击人群 → 新建圈人加"类目行为人群"（自己类目 + 购买 + 过去 30 天）取交集 → 交集 ÷ 人群总数
2. **TA 人群浓度**：在人群包上用"交集"加目标客群画像标签（消费力 L3/L4/L5 ∩ 25-39 岁女性）→ 算出符合 TA 画像的精确人数占比

**代价/风险**
**不要设绝对标准**（"60% 才算好"是错的）——放宽要求浓度自然升高、收窄要求自然降低。永远在同一严苛 TA 标准下横向比较不同渠道。

## 8. 三阶段动态调整

**何时用**
同一系列在一年里的不同月份该用同一套费比标准吗？

**怎么做**
爬坡期（新品上架/季节之初）→ 牺牲盈利换成长，可超标但关注绝对值能否追回，重点拉新；热卖期（形成江湖地位）→ 特别关注费比，超标过多追不回来，重点收割；收尾期（季末）→ 控制费比到目标范围，计算前两期缺口绝对值，重点盈利。

**代价/风险**
阶段判定错了整套预算策略就错了；判据是"销量爬坡速度与 GMV 增速"，不是日历。

## 9. 识别并保护引流先锋官

**何时用**
某链接费比高得离谱，正准备砍掉。

**怎么做**
看它的**间接成交占比**——高就说明它是引流先锋官：自身直接转化差，但主图/卖点把流量引入店铺，流量在别的链接成交从而拉高了总成交金额。把它和它间接成交贡献最大的几个链接打包进同一系列看板；只要**系列综合费比健康**，它对系统就是正向价值，**不能砍，酌情加钱**。

**代价/风险**
如果间接成交占比不高而费比仍高，**不要用这个借口护着它**——那是病例②退款率假象，去生意参谋查退款主因。

## 10. 生命周期差异化预算策略

**何时用**
同一张红绿灯表，新品和爆款不能套同一套反应。

**怎么做**

- **新品冲量期**：GSV 达标率绝对优先于费比控制，做好短期费比超标、战略性亏损的准备。月 GSV 10 万、预算 2 万、实际花到 2.5 万导致费比 20%→25% —— **多花的 5000 元是买初始权重、第一批人群资产、入场券**，占比小则亏损绝对值可控
- **爆款成熟期**：费比红线是生命线，效率优先于规模。月 GSV 500 万的爆款费比超标 2% = **10 万纯利润损耗**，5% = 25 万 → 果断停加，把预算从效率不高的收割计划转移走

**代价/风险**
判错阶段的代价不对称——把成熟爆款当新品会持续失血；把新品当爆款会永远起不来。

## 11. AI Agent 货盘梳理

**何时用**
几百上千个宝贝要按元素和类型重新打标，人工做不动。

**怎么做**
让 AI 看图打**双维度标签**——元素（光面/蕾丝/刺绣/豹纹/蛇纹）+ 类型（运动背心型/日常无痕型/蕾丝内衣型/承托聚拢型/抹胸型）→ 形成可视化货盘视图 → 为系列化核算与人群资产运营打底。跑完**人工审一遍**纠错（某耳饰被识别为耳夹，其实是耳圈，用自然语言让 AI 改分类）。

**代价/风险**
AI 有执行度问题会跑错，但从"盲"变成"只需要改 AI 跑错的那几个"已经是净收益；小众元素（如蛇纹）心智独特 → 间接成交机会弱 → 投产容易起不来、稍微加点钱就崩。

## 12. 左右两侧的优先级判断

**何时用**
不知道该往左侧（已有资产人群）还是右侧（系统外新流量）倾斜。

**怎么做**
左侧看 **TA 浓度**不看投产；右侧看**引潜比与投产**。系统会优先拿右侧的流量，右侧转化不好时才去拿左侧。

**代价/风险**
拿左侧流量看不到投产，会去比新领域抢宽度——但如果新领域宽度不够，可能拿不到好流量。

---

## 13. 收割拉新切换验证

**何时用**
想把 80% 收割 + 20% 拉新的结构往拉新方向调，但不确定产品撑不撑得住。

**怎么做**
做小幅度调整（减少收割、增加拉新）→ 看生意规模变化。**规模增长 = 对**；**规模下降 = 产品本身成交能力不强，容易被别人收割**。

**代价/风险**
这一步有真实成本（利润会短期掉），但它比"看引潜比猜"可靠得多。

## 14. 双轨取严定目标：让红绿灯判得动

**何时用**
红绿灯全店一片黄，但说不出目标该定多少；或者目标照抄上月、灯永远在原地不动。

**怎么做**
1. **轨道 A · 利润约束（底线）**：目标投产比下限 = `1 ÷ [毛利率 × (1 − 退款率)]`；目标去退费比上限 = `(毛利率 − 运营成本率) ÷ (1 − 退款率)`
2. **轨道 B · 历史基线（可达）**：目标投产比参考 = 上期实际投产比；目标去退费比参考 = 上期实际去退费比；目标 GSV（净）= 上期 GSV；目标 GMV（毛）= 上期 GSV ÷ (1 − 上期退款率)
3. **取严**：目标投产比 = `max(A, B)`；目标去退费比 = `min(A, B)`
4. 拆目标链：目标推广花费 = 目标 GSV（净）× 目标去退费比；目标流量 = 目标 GMV ÷ (上期客单价 × 上期转化率)；目标进度 = 目标值 ÷ 周期天数 × 已过天数
5. 判灯：投产绿 ≥ 目标 / 黄 ≥ 目标×0.8 / 红 < 目标×0.8；费比绿 ≤ 目标 / 黄 ≤ 目标×1.2 / 红 > 目标×1.2

**代价/风险**
利润约束的两条公式里，**去退费比上限是推导出来的、原文没有**，且依赖「运营成本率按销售额估」这个近似；毛利率估高了目标就松，估低目标就紧。投产比下限取 [[profit-model]] 的**更严版**——用更松的那版会放过实际在亏钱的投放。

## 15. 出推广红绿灯报表：口径先对账，再判灯

**何时用**
要出一份能直接用的推广红绿灯报表（给老板看 / 给团队定预算），数据是生意参谋商品明细 + 万相台商品报表导出的表。

**怎么做**
1. 跑 `scripts/red_green_report.py --input <模板>.xlsx --gross-margin <毛利率> --opex-rate <运营成本率> --period-days <周期天数>`，产出 Markdown / CSV / Excel（活公式，假设页可改）
2. **先看报表里的「口径对账」表**：模板大盘行 vs 明细逐行相加 vs 差额行，三者必须对得上；对不上说明取数或导出有遗漏，**先修数据再谈灯**
3. 再看大盘灯与分组灯（分组优先用「货品成长阶段」；「品类名称」空着就没有系列维度）
4. 交付前把「目标投产比」「目标去退费比」两个数在正文里写清楚**从哪来**（利润约束下限 vs 上期基线，取严后是多少）

**代价/风险**
大盘行不等于明细相加 —— 实测访客数差 2.3%、推广花费差 0.37%，用错会让投产比和费比都偏；比率列不要读表里预存的，一律现算，否则旧口径会污染新报表。

## 16. 万相台取数：先分清「月快照」与「三表同源」

**何时用**
要从 PG 库取万相台推广数据（做店铺级红绿灯、算计划投产、做投放体检）。

**怎么做**
1. 日期列是 **`stat_date`**，不是「日期」—— 万相台表里「日期」列整列是 NULL
2. **按自然月取**：万相台是月度快照，`stat_date` 每月只有一个值（实测都是当月 1 号），按任意日期区间过滤会静默返回 0 行
3. **三张表按计划 ID 去重**（`wxt_promotion_baobei` / `_keyword` / `_audience` 是同一批计划的不同维度视图）：表内先按计划 ID 求和，表间取花费最大的一版，**不累加**
4. **推广花费**用 `core_daily` 四项逐日相加（全站/关键词/精准人群/智能场景）；ERP 的「推广费用」一个月只有 1 天有值（月末快照），按天 sum 会错
5. **退款率**用 ERP 按订单日期的「退货金额」（`类型='真实'`）；`core_daily` 的「成功退款金额」是当天发生额，只能当趋势看

**代价/风险**
三表相加会把花费算成两倍（实测 670,818 vs 真实 330,701）→ 投产比直接腰斩一半的真相；ERP 店铺名带平台后缀（`-天猫` / `-JD` / `-PDD`），靠字符串猜会把不同平台的同名店混在一起。
