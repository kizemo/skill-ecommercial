# 第 5 章 · 组件编排：发现 → 决策 → 执行

> 用途：说明本技能库里**层级之间怎么协作**。L0 不执行动作，只负责把"今天该动什么"路由到正确的组件。

---

## 一、三层结构

```
L0  taobao-ops-playbook      ← 路由与全局公式（本文档）
     │
     ├─ 体系组件（持续运转，回答"现在什么状态"）
     │    daily-store-patrol   发现层：每日自动巡店，产出店铺级红绿灯与今日行动清单
     │    domain-growth-ops    决策层：推广红绿灯、费比治理、加减预算
     │    store-diagnosis      诊断层：钱花在哪没生效、投产假好
     │
     └─ 专项技能（按需调用，回答"这一步怎么做"）
          wanxiangtai-wujie / keyword-promo / sabc-product-tiering / ...
```

**体系组件**是持续跑的流水线，**专项技能**是被调用的工具。日常经营里，先让组件跑出信号，再按信号调专项。

---

## 二、两个组件的分工与咬合

| | `daily-store-patrol` | `domain-growth-ops` |
|---|---|---|
| **层次** | 发现层 | 决策层 |
| **回答** | 今天哪里不对？该关注谁？ | 这笔钱该加给谁、减给谁？ |
| **数据** | 直连生产库（PG），7 店自动跑 | 生意参谋 + 万相台融合看板 / 达摩盘 |
| **节奏** | 每日；另有周检月检 | 每日复核 + 每周复盘 |
| **产出** | 店铺级红绿灯表、异动清单、今日行动项 | 推广级红绿灯判定、预算调整幅度、系列化核算结论 |
| **不做什么** | 不给推广操作指令 | 不做全店异动扫描 |

### 关键：两套红绿灯口径不同，不要混用

这是组件咬合时最容易出错的地方。

| | 巡店红绿灯 | 推广红绿灯 |
|---|---|---|
| **判定基准** | **相对**——对比自身前 7 日均值 | **绝对**——对比目标 ROI / 目标费比 |
| **阈值来源** | 自适应（体量差异大的店铺通用） | 需人工设定目标值（来自预算与利润规划） |
| **回答** | 趋势变没变 | 达标没达标 |
| **典型用途** | 今天有没有异动 | 这条计划够不够好、能不能加钱 |

> **串起来用**：巡店报"费比涨、金额没涨" → 用推广红绿灯做绝对判定 → 得到双红/单红结论 → 按 `domain-growth-ops` 的四场景决策表定动作 → 若是双红再回巡店的商品层定位是哪一个宝贝的问题。

## 三、一天的闭环

```
上午：daily-store-patrol
  1. 数据新鲜度确认（各源日期不同步，先对齐）
  2. 店铺大盘红绿灯（18 核心 + 5 派生，相对判定）
  3. 流量结构定位 → 客户资产体检 → 推广计划体检 → 商品层巡检
  4. 输出：红绿灯表 + 今日行动清单 + 机会清单
        ↓
当天：domain-growth-ops（只对行动清单里的推广类项）
  5. 用目标 ROI / 目标费比做绝对判定 → 投产 × 费比两轴三色
  6. 落四场景：双绿加预算 / 投产绿费比红优化 / 投产红费比绿观察 / 双红减停
  7. 若费比类问题 → 查系列化核算（是不是把引流款误砍了）
  8. 若拉新类问题 → 引潜比 + 达摩盘两步验证
        ↓
落地：wanxiangtai-wujie（怎么改计划）/ keyword-promo（改词）/
      sabc-product-tiering（改货盘结构）/ profit-model（算账确认能不能加）
        ↓
复盘：每周重跑巡店 + 红绿灯复盘 + SABC 调级
```

**铁律**：**一次只动一个变量**（预算、人群、出价、场域、货盘），否则归因不了。

## 四、什么时候直接跳到组件，不用先读本文档

| 你手上的情况 | 直接去 |
|---|---|
| 想知道今天全店有没有异动 | `daily-store-patrol`（跑脚本即可） |
| 知道某个计划费比超了，想知道该加该减 | `domain-growth-ops` |
| 想知道该建哪种计划、参数怎么设 | `wanxiangtai-wujie` |
| 想知道这个链接的费比为什么假高 | `store-diagnosis` → `profit-model` |
| 不知道从哪开始 | `taobao-ops-playbook`（本文档） |

---

## 五、组件间的三条边界

1. **发现 ≠ 决策。** 巡店只说"哪里不对"，不替运营决定加多少预算——那需要目标值和利润约束，属于 `domain-growth-ops`。
2. **决策 ≠ 执行。** 红绿灯判完是"该减 50%-80%"，具体改哪个计划、改哪个定向，属于 `wanxiangtai-wujie`。
3. **全店层 ≠ 单品层。** `domain-growth-ops` 的系列化核算**必须按系列**；单品视角会把引流款误判成红灯（这是 ch06 病例①的典型误杀）。
