## 二、GBRain 在本次任务中的实际作用

### 做了什么

| 动作 | 结果 |
|---|---|
| 注册 source `taobao-operation` | `gbrain sources add`，纳入 host brain |
| 批量导入 | **2013 / 2082 页导入成功（96.7%）**，24077 chunks，490 秒 |
| 抽取链接图谱 | `gbrain extract links --source db`，2013 页全量扫描 |
| 页面级取回 | `gbrain get --source taobao-operation`，取回 45 篇核心素材 |
| 统计 | `gbrain sources status` / `gbrain stats` |

### 遇到的真实问题（均已处理或如实记录）

**1. pglite 单写锁**
host brain 被 Codex 会话启动的 `gbrain serve`（stdio）独占，CLI 全部返回 `pglite_busy`。杀掉 serve 后 CLI 可用，但 harness 会自动重新拉起 —— 最终采用「杀进程 + 把全部 GBRain 命令放进同一次调用」的方式抢时间窗。

> 附带发现：Codex 的 `config.toml` 配的是 HTTP `http://127.0.0.1:3131/mcp`，但实际跑的是 stdio serve，**3131 从未监听** —— 这正是 `gbrain doctor` 报 `bootstrap_harness_health` FAIL 的原因。本次未修改该配置。

**2. 69 个文件导入失败（slug 命名冲突）**
知识库 frontmatter 用 Obsidian 裸名 slug（如 `slug: 汉堡包计划`），GBRain 要求路径派生 slug（`02-knowledge/30-流量与推广/汉堡包计划`）。**未修改知识库**（那会破坏用户的 vault 约定），改为按路径 slug 用 `gbrain get` 单独取回。

**3. 中文全文检索失效**
GBRain 的 tsvector 使用英文分词器，中文查询零命中：

| 查询 | 结果 |
|---|---|
| `search "汉堡包计划"` | No results (keyword_zero) |
| `search "诊断"` | No results (keyword_zero) |
| `search "skill"` | 29 条 ✓ |
| `search "workflow"` | 0 条（英文但词不存在） |

**根因**：PostgreSQL 默认英文分词器不切分 CJK。GBRain 无 slug/分词策略开关可调。

**4. embedding 未启用**
`config.json` 中 `embedding_disabled: true`。可用的 embedding provider：`claude-cli`（仅聊天）、`ollama`/`lmstudio`/`llama-server`（本地，但**本机未运行**）、`minimax`（需 MINIMAX_API_KEY，且本机 config.yaml 里的 key 指向 Anthropic 兼容聊天端点，不含 embedding 能力）。

启用 embedding 需付费 provider key + 用户明确同意（GBRain 自身也如此提示），**本轮未擅自开启**。

**5. `think` 综合合成跳过**
host brain 未配置 chat-model key（`models.think → anthropic:claude-opus-4-7`，但 `ANTHROPIC_API_KEY` 缺失），`think` 只能返回已收集证据、不做合成。`claude-cli` provider 状态为 ready，但需要确认其模型标识才能指定。

**6. 链接图谱稀疏**
抽取结果：`links_created: 117`，`skipped_missing_target: 5370`。原因：知识库 Phase 2 迁移压平了目录结构，但笔记内的 wikilink 大量仍指向旧路径（如 `[[陪跑/2026-05-10-...]]`），**断链率很高**。这本身是知识库的一个待修复问题。

### 因此，本次分析采用的三条路径

1. **GBRain 结构层** —— 入库、类型/标签统计、链接图谱、页面级精确取回（45 篇）
2. **只读广度扫描** —— 子代理按模块抽样盘点，产出带数字与出处的结构化清单
3. **直接精读** —— 对高信息密度文件逐篇精读（体系概览、课程讲义、实战提炼）

## 三、已识别的口径冲突

制作过程中发现素材之间存在不一致，**在各 skill 中已显式标注「口径冲突，需复核」**：

| 冲突项 | 口径 A | 口径 B | 涉及 skill |
|---|---|---|---|
| 爆款阶段时间 | 打标 0-7 / 起量 7-21 / 爆发 21-45 / 稳定 45-90 天 | 打标 1-7 / 起量 8-15 / 爆发 16-30 / 稳定 31+ 天 | `skill-ecommercial`、`hit-product-lifecycle` |
| 体验分红线 | 店铺体验分 < 4.6 → 失搜索权重 + 无法报名大促 | < 4.2 分无法报名官方活动 | `compliance-medical` |
| SABC 预算占比 | S 60-70% / A 20-25% / B 5-10% / C 0% | S 50% / A 30% / B 15% / C 5% | `sabc-product-tiering` |
| 流量结构 | 免费 60 / 付费 30 / 内容 10（健康店） | 推荐+内容 85%+、免费搜索 <5% | `skill-ecommercial`（已注明口径来源不同） |

**处理原则**：不私自选一个。两处都写，并标明各自出处与适用场景。
