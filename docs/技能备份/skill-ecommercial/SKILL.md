# 电商运营技能库总纲与路由

> **铁律：先定位环节 → 再取公式阈值 → 最后才谈动作。顺序反了就是在用推广掩盖资产问题。**

**来源**：`taobao-operation` 知识库（GBRain source `taobao-operation`，2013 页）｜**版本**：2026.10｜**层级**：L0 总纲

本 skill 是整个电商运营技能库的**入口**。它不负责执行具体动作，只回答三件事：
**① 我现在在哪一环？② 这一环该用哪个 skill？③ 关键公式和阈值是多少？**

---

| | 场景 | 去哪 |
|---|---|---|
| **用** | 不知道该用哪个技能；要全局公式与阈值；跨环节决策（新品立项 / 大促 / 放量）；要出推广红绿灯报表但不知道目标值怎么定 | 本文档 → [ch04 选路决策树](../../../skills/skill-ecommercial/chapters/ch04-选路决策树.md) → 对应 skill |

| **不用** | 要竞品实时数据 | 生意参谋 / 达摩盘自取 |
| **不用** | 非淘系平台（京东 / 拼多多 / 抖音） | 本技能库只覆盖淘系方法论 |
| **不用** | 医疗器械资质的具体办理流程 | `compliance-medical` 只覆盖合规红线 |

## 一、2026 运营环境：四个已经不可逆的变化

任何诊断和方案都必须建立在这四条之上，否则会给出过时的建议。

| 变化 | 事实 | 运营含义 |
|---|---|---|
| **流量格局倒挂** | 推荐+内容流量占比 **85%+**；30 元以上商品免费搜索流量 **< 5%** | "优化搜索"不再等于"优化标题"；搜索只剩高意图入口 |
| **考核口径换锚** | 平台核心指标从"转化率→UV 价值→展现价值"改为 **GSV（总销售额-退款）** | 退款率直接吃流量，"刷单式增长"是负收益 |
| **爆款角色降级** | 爆款 = **引流工具 + 层级工具**，不再直接盈利 | 利润要靠 A 级承接、靠私域复购，靠爆款硬扛利润必然亏损 |
| **流量资产化** | 人群资产厚度决定免费流量分配；部分品类免费成交占 82%+ | 高 ROI 的根因常是"人群资产"而非"出价技巧" |

> 推论：**先看资产，再看流量，最后看推广。** 顺序反了就会一直用付费掩盖资产问题。

## 二、四大金刚（平台考核口径）

| 指标 | 定义 | 权重 | 关键动作 |
|---|---|---|---|
| **GSV** | 总销售额 − 退款 | ★★★★★ | 提客单、降退款、提复购 |
| **扣佣行为** | 参与平台佣金活动 | ★★★★★ | 首单礼金 / 秒杀 / 百亿补贴 |
| **内容成交** | 短视频 + 直播渠道成交 | ★★★★☆ | 超级短视频 + 小红书种草 |
| **动态体验分** | 物流 + 商品 + 服务 | ★★★★☆ | 顺丰、48h 发货、24h 售后 |

**新增高权重维度**：退款率（超行业均值 2 倍 → 直接限制流量）、复购率、互动率。

## 三、最常用的 10 个公式

完整 15 条见 [ch02-核心公式手册](../../../skills/skill-ecommercial/chapters/ch02-核心公式手册.md)。

```
销售额          = 流量 × 转化率 × 客单价
爆款销售额      = 点击率 × 转化率 × 客单价 × 流量     （优先级：点击率 > 转化率 > 客单价 > 流量）
利润            = 销售额 × 毛利率 − 运营成本 − 推广费用
盈亏平衡 ROI    = 1 ÷ 毛利率
斩杀线          = 固定成本 ÷ (毛利率 − 推广费用占比)
成交机会        = 优先展现权激活人数 × 货品曝光场域数量 × 匹配商品数量   ← 万相台无界
真实投产        = 投产 × (1−退款率) × (1−间接成交占比) × 拉新成交
顺逆差          = 单品成交金额占比 − 单品推广花费占比
系列去推费比    = 系列推广花费 ÷ (系列成交金额 − 系列退款金额)   ← 系列化核算用这个
UV 价值         = 客单价 × 转化率；点击单价上限 = UV 价值 ÷ 控投产目标
推广目标投产比  = max(1÷[毛利率×(1−退款率)], 上期投产比)      ← 双轨取严，见 domain-growth-ops ch09
推广目标费比    = min((毛利率−运营成本率)÷(1−退款率), 上期去退费比)
```

## 四、店铺生命周期四阶段

| 阶段 | 时间 | 核心动作 | 目标 | 对应 skill |
|---|---|---|---|---|
| **打标期** | 第 1-7 天 | 多渠道打标 + 基础销量 + 素材 | 新品标签初始化 | `hit-product-lifecycle` |
| **起量期** | 第 8-15 天 | 超级短视频 + 首单礼金 + 秒杀 | 进类目前 20 | `hit-product-lifecycle` |
| **爆发期** | 第 16-30 天 | 全站推广放量 + 叠标 + 竞品截流 | 进类目前五 | `wanxiangtai-wujie` |
| **稳定期** | 第 31 天+ | 降付费占比 + 多链接矩阵 + 私域复购 | 整体盈利 | `profit-model` + `customer-asset-ops` |

**品类周期差异**：非标品 15-20 天｜中客单标品 3 个月｜低客单标品 5 个月｜高客单 1000 元+ 45 天以上。

## 五、全店矩阵：S/A/B/C 分层

| 等级 | 数量占比 | 角色 | 推广策略 | 预算占比 |
|---|---|---|---|---|
| **S 级** | 5% | 战略大爆款 | 全站+直通车+引力魔方，冲量不计短期利润 | **50%** |
| **A 级** | 15% | 利润款 | 控 ROI + 好货快投，优化投产 | 30% |
| **B 级** | 30% | 动销款 | 好货快投 + 趋势明星，低预算养人群 | 15% |
| **C 级** | 50% | 新品/清仓 | 新品中心测试，优胜劣汰 | 5% |

> 矩阵逻辑：**S 级引流 → A 级利润 → B/C 级补充测试 → 私域沉淀复购**。
> 详情见 `sabc-product-tiering`。

## 六、诊断入口：先跑这一步再做任何方案

**唯一单一指标**：`领先率 = 新客成交 ÷ 总成交`

| 领先率 | 判定 | 动作 |
|---|---|---|
| ≥ 80% | 普通店铺合格线 | 正常推进 |
| 70-80% | 头部 KA 可接受区间 | 继续积累 |
| 50-70% | 资源浪费在收割 | 查定向与出价 |
| < 50% | 主要在跑收割 | 停掉收割型定向 |
| < 30% | 几乎全是老客在买 | 拉新链路已断 |

**四层分析法**（详见 `store-diagnosis`）：
店铺报表（整体费率）→ 商品报表（按花费排序看直接/间接成交比）→ 单品领先率 → 定向分析（转化发生在"最后一次访问来源"=收割）。

**关键判据**：
- 间接成交 = 直接成交的 2 倍 → 该品投放完全无效
- 第一次访问转化率 > 最后一次访问转化率 → 在跑拉新；反之在跑收割

> **这套判据只负责"发现问题"。** 要把它变成"今天加多少钱、停哪个计划"，走组件编排：发现层 `daily-store-patrol` 出每日红绿灯 → 决策层 `domain-growth-ops` 用**目标 ROI / 目标费比**做绝对判定 → 执行层 `wanxiangtai-wujie` 改计划。详见 [ch05-组件编排](../../../skills/skill-ecommercial/chapters/ch05-组件编排.md)。

## 九、五条不可违反的运营原则

1. **预算决定流量圈层**，预算是最核心的变量 —— 日预算 50 元只能买到老客。
2. **推广的问题要在单品中找答案** —— 推广只是放大器，不是修复器。
3. **全站推广不抢搜索流量**，付费成交反而提升自然搜索权重。
4. **特定 ROI 下只有一个坑位** —— 竞品降 ROI 就会抢走你的流量。
5. **放量要循序渐进**，每次增幅 ≤ 50%。

## 十、常见误区与红线（Common Rationalizations / Red Flags）

### 常见推托

| 说法 | 实情 |
|---|---|
| "总纲里有公式，我照着做就行" | 总纲只定位不执行。执行要进对应技能的判定表，否则会漏掉它成立的前提条件 |
| "先出报表，指标以后再补" | 目标投产比 / 目标费比错了，灯全错。目标必须双轨取严（利润约束 + 历史基线取严），不能手工填 |
| "两处写法不一样，我挑一个用" | 口径冲突要**并列**标出并打 ⚠️，不替用户选；选错一次，后面所有决策都跟着错 |
| "阈值是旧快照，我用平台最新公告" | 可以用，但要标注「当期口径」并与快照分开算，不能混进同一张表 |

### 红线（发现即停，先换路径）

- **在本入口直接出报表** → 推广红绿灯报表走 `domain-growth-ops` 的 `scripts/red_green_report.py`，不在这里手搓。
- **手工设目标投产比 / 目标费比** → 走双轨取严（`domain-growth-ops` ch09）。
- **只用领先率一个指标就下全店结论** → 领先率是"发现问题"的判据，不是"解决问题"的结论。
- **把系列化核算按单品做** → 引流款会被误判成红灯（`domain-growth-ops` ch06 病例①）。
- **把本文阈值当平台现行规则引用** → 阈值是 2026 上半年快照，引用前先核对当期公告。

## 十一、输出格式（Output Format）

用本入口回答时，按这四行输出；缺行等于没答完。

```
1. 环节定位：<生命周期阶段> + <领先率档位> + <判断依据>
2. 目标技能：<skill 名> + <为什么是它>（ch04 决策树的哪一行）
3. 关键公式 / 阈值：<公式> + <数值> + <来源章节或实测出处>
4. 下一步：<进哪个 skill 的哪一章>，或 <可直接跑的命令>
```

- 第 3 行的每个数字都要能指到出处；知识库没覆盖就写「素材未覆盖，未验证」，不推算、不编。
- 涉及推广红绿灯时，第 4 行额外给出**目标投产比 / 目标去退费比的取严过程**（哪条轨道更严、为什么）。
- 结论有前提时，把前提和结论写在一起，不要只给结论。

- 医疗器械相关内容仅适用于医疗器械类目，其他类目不适用 `compliance-medical` 的禁用词表。
